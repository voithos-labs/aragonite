# Changelog 0.11

Newest first; the index is [`../changelog.md`](../changelog.md).

### 0.11.4: typing beside a huge last block at full speed again

- **Typing beside a huge list, quote or table at the end of the document is back to full speed.**
  In 0.11.3 every keystroke, Enter or Backspace above a container that ends the document copied
  that container's bytes once, which came to about a millisecond per key at 10 MB. Now it only
  looks at how the container ends, so the size of the block below you doesn't matter.
- **A block you jump to stays in view while the images above it load.** `scrollTo`, a search
  match, or a heading or footnote link in a long document used to land the block, then let it
  slide off screen once the pictures above it finished loading and grew. It stays where it landed
  now.
- **Behavior change: `scrollTo` with `block: 'center'` keeps the block where it landed**, like
  `'nearest'` already did. A key, click, touch or wheel in the editor hands the view back; pass
  `hold: false` for the old behavior of letting go once it settles.

### 0.11.3: an undo that always undoes something, plugins that can't half-write your document, and edits that read back like a reload

- **A plugin that throws while you type no longer leaves a half-written document.** When a
  container's `rebuildRaw` throws on a keystroke, the key rolls back: the typed character
  disappears, `getSource()` is unchanged, and `error` fires with origin `commit` and `op: 'input'`.
  Before, the throw left the container half written and said nothing.
- **Alerts and footnotes keep the lines you didn't touch.** Type into a GitHub alert or a footnote
  definition and every other line stays as you spelled it (`>b` stays `>b`). Before, the first edit
  respelled the whole body.
- **Edits around a code fence you haven't closed read the way a reload does.** Enter after an
  unclosed fence, typing its third backtick above a blank line, or pasting blocks after it keeps the
  lines below inside the fence. Before, the editor showed them outside it until you reloaded.
- **A whitespace-only last line stays the way you typed it.** A file ending in an unended line of
  spaces keeps that line through edits beside it, and Enter or Backspace above it no longer adds a
  final line break.
- **On Firefox, typing over a heading's whole text in live mode leaves the caret after what you
  typed,** at the top level and inside lists and quotes. Before, the next key could land in the
  block below.
- **A few more edits no longer leave a document that reads differently after a reload:** deleting
  the only character under a quote line holding just `>`, emptying the one-character line under a
  one-line quote, typing a list marker onto a whitespace-only line above another, and a keystroke or
  split that merges a list with the block below it across a blank line.
- **Firefox stops reporting a ResizeObserver loop when you click into a long table.** A table that
  windows its rows could keep the height it was held at during load, and the next click let go of it
  in the middle of the browser's size reports. Firefox then fired "ResizeObserver loop completed
  with undelivered notifications" at `window.onerror`, which your error tracker probably saw too.
- **A production build no longer carries the editor's dev-only checks.** The last few that slipped
  past the strip now go too, about 3 KB gzipped off a minimal app (319 KB to 316 KB).
- **Ctrl+Z never does nothing any more.** Type a letter and delete it, or paste a selection over
  itself, and that step is skipped, so one Ctrl+Z takes back the edit before it.
  `canRunCommand('history.undo')` and `'history.redo'` now answer `false` when there's nothing to
  undo or redo, a fresh document included, so an undo button can show as disabled.
- **Undo and redo can't change the document while they put it back.** An empty heading the caret
  left during an undo used to turn into a paragraph, wiping the redo stack and leaving text that was
  never in the history.
- **An undo while a source edit is still open** (a shown math source, a diagram's edit box) saves
  that edit as its own step first, so the undo takes it back and redo brings it back.
- **Tab in a text block undoes with the typing around it,** so one Ctrl+Z takes back both.
- **Changing a code block's language, committing a plugin's source, and cutting from a code block
  are each their own undo step.**
- **A keystroke's `edit` event fires inside the edit,** so a decoration source that invalidates from
  an `edit` handler re-runs a tick later, as it already did after every other edit.
- **A footnote's lazy lines read like a list item's.** A continuation line in a footnote definition
  indented less than four columns keeps its leading spaces as indent, not text. The file's bytes
  don't change and edits keep them, but the editor no longer draws those spaces, a plain-text copy
  leaves them out, and a plugin reading the definition's child `raw` sees the text without them.
- **New on `/plugin`: `rebuildStripRaw`, `quoteLines` and `hangingIndentLines`** (with `LineCodec`,
  `LinePlace` and `BodyLine`), for a container that puts a prefix on every line, so its rebuild keeps
  untouched lines byte for byte.
- **Upgrade note (plugin authors):** `DraftCloseCause` has a new member, `'undo'`. The editor passes
  it when an undo or redo is about to replace the document, and your draft may save then, the same
  as on `'mode-change'`. A `switch` over the cause that checks it handles every member stops
  type-checking until it handles `'undo'`; usually `if (cause !== 'document-swap') commit()` is the
  fix. The `close` also ends your draft, so a box that stays open after it needs a fresh one.
- **Upgrade note (plugin authors):** the container conformance kit's `declarations` cell now edits
  one child of your `deepNesting` fixture and fails when `rebuildRaw` rewrites any other line or
  drops the edited child's new bytes. A rebuild that re-emits the whole body fails it when your
  fixture is spelled differently from what the rebuild writes; `rebuildStripRaw` handles that for
  prefixed containers.

### 0.11.2: plugin blocks in React and Vue, an editor that fills its box, and clicks that land where you pressed

- **An editor given a height stays that tall.** A React or Vue `<Aragonite>`, a `createEditor`
  target or the element around a Svelte `<Editor>` with a height now keeps the editor inside it:
  it scrolls there, and a long document windows. Before, the editor only filled its host inside a
  flex column; anywhere else it grew to the whole document and the page scrolled.
- **A click lands where you pressed it.** When the press closes an open inline formula and the line
  moves under the pointer, the caret still goes where you pressed. Before, a held press in Chrome,
  or any press in Firefox, could open the next formula instead. A right-click's caret works the
  same way, on a formula, in a block's padding or on text.
- **ArrowUp and ArrowDown onto a paragraph holding only a linked picture select the picture** in
  live and preview-inline mode, like they do for a picture on its own. Before, Chrome lost the
  caret. In preview-inline, ArrowLeft and ArrowRight do the same.
- **A plain list item sits right after its marker in source mode**, even in a list with to-dos. A
  to-do's `[ ]` now draws after the list's marker column, where it sits in the file, instead of
  padding every bullet out to the to-do's width. Live and reading mode look the same as before.
- **Scrolling back up a long document leaves the scroll alone in Safari.** A block coming back
  into view can lay out a fraction of a pixel taller or shorter than it did on the way down, and
  the editor used to nudge the scroll to make up for it, which could stall a momentum scroll. A
  difference under a pixel now counts as the same height.
- **Block math's preview keeps up with its source.** Typing into a shown `$$` source through an
  input method (Japanese or Chinese, say) left the committed text unhighlighted in Chrome, and the
  preview beside it a step behind, until your next key. An undo that put an older formula back in
  the source left the preview drawing the newer one. Both catch up right away now.
- **Pasting text full of unclosed `<!--` or `<?` no longer freezes the editor.** Those took the
  inline parser quadratic time, so a 40 KB paste could stall it for seconds.
- **Links read the way CommonMark reads them.** `<!-->` closes an HTML comment, `[a][ ]` is plain
  text, labels match without caring about case the Unicode way (`[ẞ]` finds `[SS]: /url`), and in
  `[foo][bar][baz]` with only `[baz]` defined, `bar` is the link.
- **Bare links stop where they should.** `http://"quoted"` and a `www.` with no real domain after it
  stay text (`http://localhost` still links). A link stops where a footnote, inline math or emoji
  starts, so `https://example.com[^1]` keeps its footnote, and at a `[` that might open a link, so
  `http://a.co/[a [b` links `http://a.co/`. With footnotes on, `[x][^a]` reads as `[x]` and the
  footnote, not one broken reference.
- **Production builds leave the editor's dev checks behind**, about 15 KB gzipped off an app built
  with Vite. Any bundler that resolves the `production` export condition gets a copy of the checks
  that does nothing (Vite and webpack do by default; esbuild needs `--conditions=production`).
  Your toolchain now has to read a package's `exports` map, which every current one does.
- **`configureEditorEnv({ isDev: false })` turns the dev checks off along with their warnings.**
  Before, it only silenced the warnings, so the checks kept running with nowhere to report.
- **Plugin blocks drawn with your own React or Vue components.** `reactBlockView` (from
  `@voithos-labs/aragonite-react`) and `vueBlockView` (from `@voithos-labs/aragonite-vue`) take a
  component and give you a block view. Put `<LeafContent>` where the editable text goes and
  `<BlockChildren>` where the child blocks go; it works for text blocks, click-to-edit blocks and
  containers. The component reaches your app's providers through `wrap` (React) or `app` (Vue).
- **A click-to-edit block's component gets `draft`**, the source as you type it while the block is
  open (`null` while it's folded), so a preview can follow each key before the edit commits.
- **Click-to-edit blocks without Svelte.** `defineBlockView({ surface: 'render-primary' })` draws a
  block that shows a rendered view until a click opens its text, block math's shape. Hand
  `ctx.leaf.attachRendered` the rendered half, and `ctx.leaf.attach` the text element when
  `state.revealed` turns true. The editor does the rest: where the click lands, the caret, IME,
  and the one undo step the edit becomes when you leave.
- **`defineBlockView` blocks are supported in apps that don't compile Svelte** (the prebuilt copy).
- **A leaf view's `afterInput` hears every change to its text, once.** In 0.11.1 it ran on each
  `input` event, so it missed the edits the editor writes itself (a Backspace, a paste, Enter) and
  ran mid-composition. Now it runs once per change, an IME commit and an undo included, and never
  while you're still composing.
- **A DOM container view handed the box its children already sit in keeps them**, caret included,
  instead of remounting them.
- **The plugin guide has a React and Vue page**, and its text block, container and whole-document
  recipes now lead with `defineBlockView`, with Svelte as the "already in Svelte" path.
- **Upgrade note:** if you sized the editor with your own `.editor { height: ... }` rule, size the
  element you mount it into instead. The editor fills that element now, and its own height rule
  wins over a plain `.editor` selector.
- **Upgrade note (block components):** `snapCaretToPoint(x, y)` is now `readSnapAtPoint(x, y)`. It
  reads the point right away and returns a function to call once the caret is placed.
- **Upgrade note (plugin components):** `leaf.repaintSource()` is gone from `createEditableLeaf`.
  A painted source repaints itself after an IME commit, and `onSourceEdit` hears that commit like
  any other edit, so a wrapper around `oninput` that called it can go.

### 0.11.1: deletes the editor decides, lists that line up, and reading mode as a page

- **A to-do you add right above or below a to-do list joins it.** Typed, pasted, or picked from
  the slash menu or Insert, the new row used to sit one blank line away as a list of its own, with
  that slightly wider gap. Now the blank line goes and it's one list. The same holds for any list
  item next to a list of its kind (same bullet, or same `1.` / `1)`), and for a paragraph you turn
  into one there.
- **A plugin block's command can change what the block stores in the file.** The command context
  has `replaceRaw(raw)`, which rewrites the block's own bytes as one undo step, keeps the caret on
  the text it was in, and waits for a source the user still has open. Before, a plugin leaf only
  had `updateMetadata`, which changed the block on screen and was gone on reload.
- **`updateMetadata` on a plugin leaf writes nothing and says so**: a dev warning and an `error`
  event that point at `replaceRaw`. Containers keep using it, since their `rebuildRaw` writes it
  into the bytes.
- **Plugin blocks without Svelte.** `defineBlockView({ surface, mount })` on `/plugin` draws a block
  with plain DOM, into an element the editor makes for it. With `surface: 'leaf'` you hand the editor
  an element and it edits the block's text there (caret, IME, undo and selection work like a
  built-in block's), and the chrome around it is yours. With `'container'` you hand it a box and the
  child blocks mount and window inside it. With `'none'` you draw all of it and give the editor
  `focus` and friends from your handle.
- **A view's `update` can return `false` to be mounted again from scratch**, and
  `watchDocument: true` updates it on every document change. A throw in `mount` or `update` shows
  the block's source with the usual notice, the same as a Svelte block that throws.
- **Upgrade note (plugin components):** a component that builds its own `BlockCommandTarget` for
  `getCommandContext` adds `replaceRaw(raw)`.
- **Upgrade note (plugin containers):** `reorderChildren` takes no fields now, so a container
  whose children reorder declares `reorderChildren: {}`. `renumberMarkers` is gone: only a
  numbered list could ever use it, and a reorder renumbers one on its own.
- **Up and Down in a wrapped paragraph go where the caret shows.** ArrowUp from the start of a
  wrapped paragraph's second line used to jump to the block above in Chrome and Firefox, and in
  Safari End on a middle line then ArrowDown jumped to the block below. Same fix for list items,
  and for the first Shift+Up or Shift+Down from a caret in a table cell.
- **Leaving a block from a wrapped line keeps your column**, so Down from the start of the last line
  lands near the start of the next block, not at its far end.
- **Cmd+Backspace and Cmd+Delete at the start of a wrapped line take that line's text**, not the line
  above's.
- **Erasing the last line of a block that sits above a blank line no longer leaves an extra empty
  paragraph** after a reload. The editor now shows the same blocks the file reloads as.
- **A `:::` or `$$` typed a few blocks below an unclosed one closes it**, the way a reload reads it,
  even when that pairs up the fences in between differently.
- **Deleting or moving a block that sat between a paragraph and a table, a rule or indented code
  keeps that block what it was**, with a blank line above it. Deleting a rule above indented code
  used to turn the code into paragraph text.
- **Enter at the start of a paragraph right under another block leaves an empty line to type on.**
  It used to do nothing you could see.
- **Typing on a code block's opening fence doesn't delete its closing fence anymore.** Type or
  backspace on the ` ``` ` line, or find/replace or range-delete the opener, and every byte
  below stays put. The old closer reads on as a fence and pairs up with the fences below the way a
  reload pairs them. Put the backtick back and the opener takes its closer back, so every fence
  returns to where it was (undo does too). A fence you type on a line of its own still gets a
  closer of its own. Same goes for `$$` blocks and plugin kinds that use `fenceRawWrite`.
- **Upgrade note (plugin openers):** `BlockOpener.readingNotFinal` is now a pair,
  `{ notFinal(raw), mayClose(line) }`. Move your old function to `notFinal`. `mayClose` says yes to
  every line your opener could take as its closer (saying yes to more is fine), and the kind
  conformance kit checks it against your fixture's closer.
- **Upgrade note (plugin fence kinds):** if your opener claims a fence, declare
  `readingNotFinal: fenceReading` (new on `/plugin`), so an edit pairs your fences the way a reload
  does. The kind conformance kit fails a fence kind without it, and it also fails a `rawWrite` that
  deletes bytes the write didn't touch. `UnfinishedReading` has a new optional `readsOn`.
- **A list item's wrapped lines line up under its first line's text**, for bullets, numbers and
  to-dos in every mode and font. In a proportional font the second line used to start up to 15px to
  the right.
- **An item that opens with a picture draws its number or bullet at the picture's top**, not under
  it.
- **A heading inside a list item draws its number or bullet at the heading's size and weight**, the
  way a word processor numbers headings, and its wrapped lines line up the same way.
- **A nested list item of a different kind paints only its own marker.** A numbered item or to-do
  inside a bullet used to pick up the bullet too (`•1.`, `•☐`).
- **Every list item draws its own marker**, including one that opens with a code block, a quote, a
  table or another list. Those used to show no marker at all, and in source mode their `- ` or
  `1. ` was invisible.
- **A list keeps its text in one column**, as wide as its widest marker, so `9.` and `10.` line up.
  Later paragraphs in an item start at its text too, and so do a nested list's markers.
- **Pressing a bullet in live mode puts the caret at the item's start**, where it used to swallow the
  next key. An empty to-do's box sits on its line now, not a few pixels off it.
- **End then Backspace in a list item's heading empties it the way a top-level heading does.** It
  used to leave stray `#`s (`- #  #`).
- **Typing `#` in front of some words makes a heading again, even with a `#tag` plugin.** The `#`
  turned `few` into a tag, the caret jumped past it, and the space landed after the tag. Now the
  caret stays where you typed with the tag's source showing, so `#` then space gives you
  `# few words`. Same fix for `[` before `^a]`, wikilinks and directives.
- **What you type into a shown source is written as you type it**, for inline math, tags, footnote
  references, wikilinks and directives. The source stays shown while your caret is in it and
  renders when you leave, so a formula halfway through an edit (`$x $`) doesn't flicker.
- **Escape on a shown source closes it and keeps your edit.** It used to throw the edit away;
  Ctrl+Z is the undo now.
- **Undo, redo and `setSelection` can put the caret inside a tag or formula**, which opens its
  source, instead of pushing the caret past it.
- **Firefox and Safari no longer break Windows line endings.** In a file saved with `\r\n`, typing,
  pasting, Backspace or Delete at the end of a line could split the pair and leave a stray carriage
  return in the file. Backspace there also ate the line break instead of the last letter.
- **ArrowDown into a code block keeps your column in Firefox and Safari**, instead of jumping to the
  start of the code, and ArrowUp at the start of a line goes to the line above instead of leaving
  the block.
- **One arrow press crosses an entity, an emoji or a hidden decoration in Safari and Firefox**, Shift
  included, and so does a Windows line ending. They used to take two presses, or land one character
  past.
- **Shift+Enter works in code blocks and table cells in Safari**, where the key was dropped.
- **A soft keyboard's line break in a paragraph writes a line break**, where it did nothing.
- **In Firefox, clicking past a run of emoji at a line's end puts the caret after the run.**
- **A numbered list keeps its starting number** when you move an item (Alt+Arrow or drag), delete
  its empty first item, or indent an item into or out of a sublist. A list starting at 8 used to
  renumber from 1.
- **Deleting across a numbered list keeps its numbers in order.** Delete, Backspace, Cut, or typing
  or pasting over a selection that spans some items used to leave a gap (`9.` then `11.`), and a
  list that lost its first item lost its starting number too. Deleting an item selected as a whole
  renumbers the rest the same way.
- **Deleting the first item of a numbered list right under a paragraph leaves a list.** The rest
  used to fold into the paragraph's text.
- **`getDiagnostics().recordInput()` records what someone did in the editor**: keys, input events,
  compositions, pastes, drops and pointer presses, into a versioned JSON file you can attach to a
  bug report. `recording.stop()` hands it back. Text stays out unless you pass `includeText`, and
  without it the file's hashes are salted, so nobody can work the document back out by guessing.
- **The demo at aragonite.dev has a "report a bug" button.** It records what you do, then opens a
  GitHub bug form and puts the recording on your clipboard to paste in. Nothing reaches GitHub
  until you submit.
- **The demo's top bar is quieter.** The modes sit in the middle (a dropdown on a narrow window),
  docs, changelog and report a bug sit on the right, and the rest (dark mode, drag handles, the
  selection menu, occurrences, under the hood) moved into a settings popover. The wordmark links to
  the repo, and the React and Vue demos draw the same bar, report a bug included.
- **Menus close on a click outside or on Escape in Safari.** Safari never focuses a clicked
  button, so the code block's overflow menu used to stay open.
- **Right-clicking a divider or a code block's text in Safari opens that block's actions again.**
  Safari selects the word under a right-click before the menu opens, and the menu used to take
  that as your selection. Paste still replaces the word Safari selected, the way macOS does.
- **Backspace and Delete take the same thing in every browser**, in every block you can type in:
  paragraphs, headings, list items, quotes, table cells, code blocks and plugin blocks. An emoji
  family, a flag or a keycap goes as one character (Firefox used to split a family), Backspace after
  a letter built from combining accents takes the last accent and Delete takes the whole letter, and
  neither ever splits a Windows line ending. The editor decides these now instead of the browser.
- **Word and line deletes take the same text in every browser too.** Ctrl+Backspace (Option+Backspace
  on a Mac) and the word Delete take the word you see: a hidden bold marker is never a word of its
  own, and what's left matches selecting that word and pressing Delete. On a Mac a forward word
  delete keeps the space after the word. Cmd+Backspace takes to the start of the line on screen.
- **Shift+Backspace does what Backspace does** beside an image or hidden formatting, where it used
  to take the letter before an image or break a bold run. Word and line deletes beside an image do
  what the plain key does too; in Safari these used to do nothing at all. A host that binds one of
  these chords in `keybindings` still gets its own command there.
- **In live mode, Backspace at a heading's start turns it into a paragraph even when a plugin
  decoration sits there.** The key used to do nothing.
- **Any delete at a block's start or end does what Backspace or Delete does there**: a word delete
  (Ctrl+Backspace, Option+Backspace), a line delete (Cmd+Backspace), Shift+Backspace, or a soft
  keyboard's delete. Word and Docs join the blocks there, and so does aragonite now; these used to do
  nothing. At a code block's start they step out of the block, like the key, and at a heading's
  start they turn it back into a paragraph. A host that rebinds or turns off Backspace in
  `keybindings` gets the same from all of them.
- **Shift+PageUp and Shift+PageDown move a selection's end a screen**, across blocks and into
  tables, and keep it on screen. They used to do nothing or scroll the end away.
- **PageUp and PageDown move the caret a screen** into whichever block is there, table cells
  included, instead of leaving it stuck in its block off screen. On a Mac they still only scroll,
  the way the system does.
- **Backspace or Delete on the line Shift+Enter just opened takes that line back**, from a key or a
  soft keyboard. Backspace used to take the letter above it, and Delete pulled the next paragraph up
  onto your text.
- **In a plugin block's shown source, typing or deleting an emoji joins the undo step of the typing
  around it** instead of taking one of its own.
- **Reading mode's keyboard is the page's.** Tab walks the document's links, footnote references
  and buttons, and the editor is a single stop (the block you last clicked or jumped to) instead of
  one per paragraph, so a long document no longer takes hundreds of presses to leave. Tab no longer
  gets stuck in a table cell or over a selected range. A click leaves no caret, arrows step from
  block to block, and a block taller than the editor scrolls a line at a time first.
- **In reading mode a heading reads to a screen reader as a heading**, and every other block as its
  text, not as a read-only edit field.
- **Reading mode gives up keyboard text selection:** with no caret, Shift+Arrow has nothing to move
  and selects nothing. Shift+click still selects from your last click, like on any web page, and
  focus follows it the way it does while editing. Drag, double-click and select-all select too. In
  reading mode `getSelection()` is `null` unless a range is selected, and `setSelection` lands a
  saved caret as focus on its block.
- **Copying a range across blocks in reading mode copies its Markdown** in every browser; Chromium
  and Safari used to leave the clipboard empty. A clicked image copies its Markdown too, and a
  selection inside one block still copies its text as shown.
- **Backspace on a reading-mode block or an editor button no longer sends Safari back a page.**
- **Upgrade note (plugin blocks):** `EditableLeafSurfaceProps` no longer carries `tabindex` (the
  editor sets it), and `EditableSurfaceAttributes`' `role` and `aria-label` are optional. Don't put
  a `tabindex` of your own on a block element; `readingTabOrderProblem` (the testing subpath) checks
  it.
- **Upgrade note:** a host that turns off `Tab` for table cells now gets the browser's Tab in a cell
  instead of a cell move.
- **In reading mode, Tab carries on from where a jump lands, in every browser.** After a footnote,
  back-marker or outline jump, Tab reaches the definition's back marker (or whatever comes next)
  instead of skipping it in Firefox, and the back marker returns you to the reference itself.
- **Upgrade note:** in reading mode `getSelection()` and `selectionChange` report `null` after a
  jump or `navigateTo`, since reading mode places no caret.
- **Leaving reading mode puts the caret where your focus was**, so the first key you type lands
  there instead of nowhere.
- **In reading mode, a click on a block's padding or chrome focuses that block**: a quote's bar, a
  list's bullet, the gutter, a nested block's frame, or the space below the last block. Tab then
  carries on from there instead of starting over at the top of the editor.
- **Upgrade note:** in reading mode `placeCaretAtPoint(x, y)` focuses the block at the point and
  returns `true`. It used to return `false` for a text block.
- **A mermaid diagram that's still drawing no longer grows the page around the editor** or snaps a
  scroll you made back to where it was.
- **On a long table, a second column insert or delete no longer misdraws the rows scrolled out of
  view** when they come back, or after an undo.
- **Replace All over a list no longer trips a Svelte warning in Firefox.** A list or quote that
  scrolled out of view used to leave its old state behind, and an edit could read it.
- **Right-clicking a tag, a wikilink, an equation, an image or another widget opens the same menu
  in every browser**, in prose and in table cells: "Edit link" first on a widget that goes
  somewhere, with the caret beside it. In Safari the widget's own selection used to win and the
  menu lost Edit link. It also reads the press you just made, even right after a click on another
  widget.
- **A right-click on an image or widget you've selected keeps it selected**, and the menu's Cut,
  Copy and Paste act on it the way Ctrl+X, Ctrl+C and Ctrl+V do, in a table cell too.
- **A menu Paste reads the clipboard after the menu closes**, so Safari's Paste prompt no longer
  draws over an open menu.
- **The block menu's Copy writes what Mod+C writes**, without the trailing line ending, and a
  clipboard that refuses the write does nothing instead of raising an error.
- **Clicking Set heading on the selection toolbar keeps its heading picker open.** Hovering opened
  it and the click shut it again. Escape closes it now too, and keeps your selection.
- **Menu Paste works in Firefox**: the right-click menus' Paste and Paste as plain text, and the
  table cell menu's Paste. They used to do nothing there.
- **Copying, cutting and pasting across blocks works in Firefox** when the selection ends on a
  block with no text, like a rule or a table scrolled out of view.
- **Text you copy in Firefox on Windows keeps plain line breaks**, and Ctrl+A then copy in an empty
  table cell copies nothing instead of a blank line.
- **A paste or a cut inside a block is its own undo step.** Ctrl+Z takes it back without the typing
  just before it, and typing right after it undoes on its own.
- **Paste as plain text into a code block (or block math) keeps the text as it is.** It used to
  write backslashes in front of Markdown characters, which only prose needs.
- **Plugin components:** a block can implement `insertPlainText(text)` beside `insertMarkdown`, so
  Paste as plain text takes its text literally. Without it, the editor escapes the text and hands
  it to `insertMarkdown`, the way prose takes it.
- **Typing next to an inline formula or entity works in Firefox.** After End, or a click to the
  right of one, Firefox parked the caret inside it and your text went nowhere; the drawn caret also
  sat on the formula's superscript. Text typed right before a line break that ends a paragraph or a
  table cell isn't dropped anymore either.
- **Ctrl+End and Ctrl+Home reach the very end or start of the text** when an inline widget sits
  there, table cells included. Firefox stopped short of it.
- **In live mode in Firefox, ArrowLeft and a click beside a hidden marker land where they do in
  Chromium**, so the caret the editor reports, and everything that steps from it, agrees across
  browsers.
- **In live mode in Firefox, Backspace that empties a heading leaves a plain paragraph**, as it
  does in Chromium, instead of a heading made only of its `#`s.
- **A click in a code block's padding lands on the nearest line in Safari and Linux browsers**, and
  a click just below a heading's letters lands at that column. Both used to jump to the line's end.
- **A click beside an equation in Firefox puts the caret next to the formula**, not at its start.
- **Escape during an image crop in Safari cancels just the crop**, and Cmd+Z right after a crop
  undoes it. Escape used to dismiss the image too, and the undo did nothing.
- **Keys on a selected image do what they'd do next to it.** Mod+Home and Mod+End (Cmd+Up and
  Cmd+Down on a Mac) leave the image for the paragraph's start or end, and the Shift keys (Home,
  End, Up, Down, PageUp, PageDown, Mod+Shift+Home and End) extend the selection with the image in
  it. They used to do nothing, and in Chromium Mod+Shift+End selected text you never picked.
- **Cmd+Up and Cmd+Down move to the block's edge wherever the browser passes them through**, not
  only on a Mac.
- **While an image crop is open, nothing types over, deletes, cuts or pastes over the image.** A
  stray letter used to replace the picture. Enter applies the crop, Escape cancels it, and Find and
  the browser's own shortcuts still work.
- **Ctrl+Z works with focus on an editor button in Firefox** (an image's toolbar, a code block's
  rail, a table's add-row button, a find bar mounted outside the editor), one step per press.
- **Ctrl+Z and Escape work after any image toolbar action**, in every browser. Closing the Alt
  text field with its button used to leave Ctrl+Z doing nothing, and after a crop or the field's
  Enter or Escape, Escape did nothing. Now Escape dismisses the image and leaves the caret just
  after it, the same as on an image you just clicked.
- **Removing an image from its toolbar leaves the caret where the image was**, Alt field open or
  not, so you can keep typing.
- **After a click on a code block's copy, run, ⋮ or language button, typing carries on in the
  block**, and Ctrl+Z works in Firefox. A second click on the language button closes its picker in
  Safari too.
- **After Reset view on a diagram, typing and the arrow keys reach it again.**
- **Shift+Arrow keeps the end of your selection on screen**, including when you extend back into
  the block you started in, and the next Shift+Arrow keeps going from there instead of collapsing
  the selection. The same goes for a selection through a tall table.
- **Shift+ArrowDown from a paragraph into a table grows the selection a row at a time**, where it
  used to stick on the table's first row.
- **A plain arrow over a selection collapses it before anything else happens.** ArrowLeft over a
  selection at the start of a paragraph used to jump to the paragraph above, and ArrowUp over one
  in the first block did nothing, so your next letter replaced it. Now Left and Right collapse it
  to the end they name, and Up and Down carry on from the end you were moving, in list items,
  headings, table cells and code blocks too. In reading mode an arrow over a double-clicked word
  steps blocks like any other arrow.
- **Shift+Home and Shift+End over a selection that spans blocks move its end to the edge of the
  line** (Cmd+Shift+Left and Right on a Mac). Firefox used to scroll the page away, and other
  browsers did nothing.
- **Cmd+Left, Cmd+Right, Cmd+Up and Cmd+Down work like Home and End on a Mac.** They're a Mac's
  Home and End, and the editor's own rules for those keys used to miss them: Cmd+Left in a list
  item landed before its marker, Cmd+Right stopped short of a trailing widget or inside a code
  chip, and Cmd+Up or Cmd+Down on a block's first or last line hopped to the next block. With
  Shift they extend the same way, Cmd+Shift+Down all the way to the end of the document.
- **`claimsChord` claims Cmd+Arrow and leaves Ctrl+Arrow alone** (the browser's word jump on
  Windows and Linux), and `reservedChords()` lists the `Mod+Arrow` edge chords only on a Mac.
- **An arrow key or an undo that puts the caret between two blocks brings it on screen in
  Firefox.** It could sit just past the edge of the page. It also scrolls only as far as it needs
  to now, instead of jumping the caret to the middle of the screen.
- **A fast drag ends where you let go**, in every browser. A quick drag from text into a table, or
  into a diagram, could end the selection a cell or two short, so Ctrl+B bolded the header instead
  of the cells you dragged over.
- **After a drag from text into a table, the selection toolbar sits below the cell you let go in**,
  not over the rows you just selected.
- **In preview-inline mode in Safari, typing after a marker appears goes where the caret is.** It
  used to land inside the code span next to it.
- **Pressing the marker of a list item that opens with a table** puts the caret at the start of that
  row's cell, not after its text.
- **A list node from `parse()` carries `markerWidths`**, how many items open with a marker of
  each width, beside `childSpans`. The editor sizes a list's marker column from it, so typing in a
  long list no longer rescans every item.
- **The find bar's pressed toggles keep their fill in Safari 15**, which can't read `color-mix`.
- **Typing, pasting or composing over a selection puts your text where the selection was.** When
  the selection took a whole block (a table, say) and ended at the start of a heading, code block,
  HTML block, math block, rule or diagram, the text went in front of that block's syntax and broke
  it: `x# Head` turned into a paragraph, and a code block lost its closing fence. It now goes in a
  new paragraph in the selection's place, before a block below and after a block above. That
  changes 0.11.0's rule case too: text typed over a selection ending on a rule now lands before the
  rule, where the selection was, not after it.
- **The consumer guide is three pages now.** The recipes got a page of their own, the desktop-shell
  and diagnostics sections share another, and the export table groups the exports by what you'd use
  them for.

### 0.11.0: React and Vue, no Svelte required, and a caret like the browser's

- **The caret looks like the browser's again.** The bar the editor draws used to land on
  half-pixels, so it smeared across two columns (washed out, a touch wide, worse at 125% or 150%
  display scaling), and about half the time it stood one pixel into the next letter. Now it sits on
  whole screen pixels, in the column the browser's own caret uses, as wide as the browser's at your
  display scale.
- **The caret takes the color of the text it's in**, a link's color inside a link, like the
  browser's caret does. `--md-caret-color` now defaults to that; set it if you want one color
  everywhere.
- **The find bar has a new look** (Finn's): a card that's itself the find field, holding your
  query, a quiet `1 of 4` count, then the case, whole-word and regex toggles beside the step
  arrows, the replace toggle and close. Step and replace stay disabled until there's a match, and
  `--search-bar-top` / `--search-bar-right` move it from its corner (10px each by default).
- **The find bar got kinder to keyboards and screen readers.** The match count is announced as it
  changes, and when Replace or All leaves no match, focus moves to the replace field instead of
  getting stuck on a disabled button. In forced-colors mode the focused bar keeps a highlighted
  edge and a pressed toggle looks pressed. Clicking anywhere on
  the bar that isn't a button puts you in the field, the focus ring shows in dark mode, and an
  invalid regex no longer pushes the bar's buttons onto a second line.
- **The open find bar moves only the block controls it actually covers.** A code block's rail, a
  diagram's toolbar or an equation's layout toggle drops below the bar when the bar sits over it,
  including as you scroll a block under it, and every other block's controls stay put. A plugin's
  own top-right hover control opts in with `data-corner-control`.
- **A find bar you've moved with `searchBarAnchor` keeps the editor's colors** in a host with its
  own theme.
- **Inserting a table row above the header, or moving a row into first place, makes that row the
  header.** The old header used to keep the flag on screen while the saved table already read the
  new first row as the header, so a reload showed a different table.
- **Turning a format off across several blocks gives each block the kind its new text reads as.**
  Un-bolding `**#**` leaves a heading, the same as it already did inside one block.
- **An emptied line after a line break no longer saves a stray backslash.** Shift+Enter, a letter,
  then Backspace (or cutting that letter) used to write `abc def\`, which a reload showed as a
  literal backslash. The empty line now behaves like a fresh Shift+Enter line: it's there while
  your caret is, and leaving it (an arrow, a click, a blur) takes it away. **Changed from 0.10.10:**
  the arrows no longer stop on an emptied line after you've left it.
- **Removing an image in live mode leaves nothing behind.** Its toolbar's Remove (and any other
  popover or menu write over a range) used to strand the markers around it, so a linked image left
  `[](u)` and a bold one left `****` on screen.
- **In live mode, the part of a format run you keep stays formatted**, the way a word processor
  does it. Cut from inside `bold` to past `and` in `Some **bold** and words`, and you're left
  with `Some **bo**d words` instead of `Some bod words`. Deleting and dragging work the same, and
  so do italic, strikethrough, code spans and links. Source mode still removes exactly what you
  selected.
- **Copy, cut and drag carry the format they cut through** in live mode, closed at the selection's
  edges (`**ld** an`, not `ld** an`), so pasting gives back what you cut, and dropping or pasting
  formatted text inside another format run joins it cleanly instead of printing `**` on screen.
- **Enter inside a code span next to a space** (`` ` |a` ``) splits the span onto both lines in
  live mode instead of leaving stray backticks on screen.
- **Typing over a selection that cuts a format run beside an empty pair** (`[](u)`) keeps the
  run's format instead of showing its markers.
- **A plugin inline kind's split setting alone decides whether a cut closes and reopens it**, so a
  pending mark and Enter now give the same answer for one kind.
- **Table cells copy and cut a selected widget** the way a paragraph does. Before, Ctrl+C and
  Ctrl+X over a plugin widget selected in a cell did nothing.
- **A grid pasted from a table cell's right-click menu fills cells**, the way Ctrl+V does,
  instead of landing as text in one cell. The menu's cut and copy now run the same steps as the
  keys.
- **Format shortcuts in a table cell format the selected range** while a widget's source is
  shown, and leave the caret where you had it, the same as in a paragraph.
- **A selected widget looks selected.** An arrow key onto a live line break, or Mod+K on a plugin
  widget, used to select it with nothing on screen, so your next key deleted something you
  couldn't see. Now a line break shows a narrow selection block at the end of its line and a plugin
  widget wears the selection tint, in paragraphs and table cells alike. An image in reading mode
  gets the tint too, since its ring only shows while you edit.
- **Typing over a link's whole text keeps the link**, and two links with different destinations
  that meet across a deleted range stay two links instead of fusing into one.
- **A selection that ends right where a rule, code block, HTML block or math block starts leaves
  that block alone.** Deleting it used to pull the block's markup into the paragraph above, so a
  rule turned into the text `al---` and a code fence lost its opener. Paragraphs and headings still
  join the way they always did.
- **Typing over a selection that ends on a rule** puts your text in a new paragraph after the rule,
  the way an IME already did, instead of writing `x---`.
- **aragonite works in React.** The new `@voithos-labs/aragonite-react` package gives you
  `<Aragonite>`: a controlled `value` with `onChange` (or `defaultValue` to start uncontrolled), a
  React `header`, every editor prop, and a ref to the editor's handle. It's marked `'use client'`
  for Next, works in StrictMode, and supports React 18 and 19. It ships in lockstep with the core
  package, at the same version.
- **The `theme` prop is enough on its own.** In an app that declares none of the editor's colors and
  uses no `aragonite-editor-theme` wrapper, `theme="light"` used to change almost nothing you could
  see while the find bar and menus still painted dark. Now every color you leave undeclared comes
  from the built-in palette in the mode `theme` names, so the menus, find bar and toolbars match it.
  Text on your page keeps your page's color, and a host that declares its own colors (or uses the
  wrapper) looks exactly as before. Forget `editor-theme.css` and a dev build says so.
- **The editor no longer leans on your page's CSS reset.** On a page without one (a fresh Vite or
  React app), it used to sit 40px wider than its container and typing scrolled the page sideways;
  now it lays out the same everywhere. What you put inside it (the header, decoration widgets and
  badges, custom inline-menu rows) keeps your page's own styles. A page rule on a bare element
  (`button { margin: 4px }`) can still reach the editor's own controls.
- **aragonite works in Vue.** `@voithos-labs/aragonite-vue` gives you `<Aragonite>` for Vue 3.3 and
  newer: `v-model` (or `default-value`) holds the document, a `#header` slot renders above the first
  block, a template ref holds the editor's handle, and every other prop is an editor option
  (kebab-case works; a boolean you leave out keeps the editor's default). It works in Nuxt as is:
  the server renders an empty container and the editor mounts in the browser. Like the React
  package, it ships in lockstep with the core.
- **Svelte is an optional peer now, and the published types don't need it.** A React, Vue or plain
  TypeScript app installs no Svelte and type-checks the package with `skipLibCheck` off. Everything
  whose types are Svelte's lives on a new `@voithos-labs/aragonite/svelte` entry.
- **Writing `source: undefined` keeps the document** instead of emptying it, from Svelte or
  `createEditor` alike.
- **Apps that don't compile Svelte get a prebuilt build automatically.** A React, Vue or plain
  bundler resolves the package to a copy with Svelte compiled in; import
  `@voithos-labs/aragonite/style.css` beside `editor-theme.css`. Svelte apps still get the source
  build, unchanged. The bundled plugins run
  everywhere; a plugin with Svelte components of its own (any custom block, for now) still needs an
  app that compiles Svelte.
- **A plugin component compiled against a different copy of Svelte says so in dev**, instead of the
  generic "block failed to render".
- **A `searchChange` event** fires once whenever what the find bar shows changes: open or closed,
  the query, the options, the current match, the match count, an error, or the count a replace
  reads out. A regex search fires once its matches land, and a replace-all fires once after its
  last block, so a host outside Svelte can mirror the find state.
- **One way to draw a plugin's UI.** An inline widget, a decoration's widget or badge, and an
  inline menu row are all a `PluginView` now: `(target, props) => { update?, destroy? }`, so any of
  them can be plain DOM. The
  editor makes `target`, sends new props through `update`, and calls `destroy` once when it drops
  the view. A pooled inline widget gets `update` when typing beside it moves it, and a decoration
  widget gets the re-run's decoration; both used to keep the props they mounted with. A Svelte
  component still works in any of the three through `svelteView(Component)`.
- **A plugin view that throws falls back and reports on `error` instead of breaking things.** A menu
  row shows the default row, an inline widget whose view or `isWidget` throws shows its
  source instead of failing its whole block, and a widget or row that throws while it's torn down
  reports instead of leaving an unhandled rejection.
- **`createEditor(target, options)` mounts the editor without a Svelte component.** It hands back
  the editor's usual handle plus `update` (pass changed props) and `destroy`, and `header` takes an
  element. It's the base the framework wrappers build on, and `EDITOR_OPTION_SPECS` lists every
  option with when a change takes effect, if you're writing a wrapper of your own.
- **Hooks you swap after mount reach the blocks already on screen.** `onRunCode`, `codeMenuItems`
  and `onPasteImage` used to stick with whatever a block mounted with, so adding a run hook later
  painted no run button on code blocks you could already see.
- **Nothing lands after the editor unmounts.** An `insertMarkdown` or image paste still running at
  unmount writes nothing and fires no event, and an `insertMarkdown` overtaken by a `source` swap
  resolves `false` instead of `true`.
- **`imageLoadPolicy` can change after mount.** It always could; the guide used to say otherwise.
- **`parse` finds every built-in block kind, whatever you import first.** A pipeline that imported
  the parser before the rest of the library used to parse with no built-in kinds, or crash at
  import.
- **Mark decorations can tell you when they're hovered.** Give a mark an `interactive.onHover` and
  it gets called on the way in, with the rect the pointer came through (and every rect the mark
  paints), then once with `null` when the hover ends. It ends when the pointer leaves, the source
  drops the mark, its block scrolls out of range, a new document loads, or the editor unmounts, so a
  card you open on hover always hears when to close.
- **Keyboard users get there too.** The new `decorations.activateAtCaret` command runs the
  `onActivate` of the mark under the caret. It ships without a chord; bind one through
  `keybindings` or call it with `runCommand`.
- **`interactive.onClick` is optional now**, and `interactive` needs at least one of its three
  handlers. A mark with `onClick` takes the click. A hover-only mark lets clicks, drags and
  double-clicks through to the text under it, and keeps the text cursor.
- **Where interactive marks overlap, the shortest range wins**, then the earlier source, for the
  pointer and the keyboard alike. Clickable marks also paint above plain ones (a search highlight,
  say), whatever order their sources registered in.
- **Marks in table cells behave.** A clickable mark keeps its click when another source paints a
  plain mark on the same cell (it used to lose it to whichever came last), and a throwing `onClick`
  there reports the cell's path on the `error` event, not the table's.
- **Upgrade note:** since `onClick` is optional, calling `dec.interactive.onClick(...)` yourself
  needs a `?.` now (TypeScript's `TS2722`, "Cannot invoke an object which is possibly
  'undefined'").
- **Upgrade note (plugin API):** the per-slot drawing fields are gone in favor of `view`.
  - `registerInlineWidgetKind`: `buildWidget` becomes a view that fills the span the editor gives
    it, and `mintWidgetShell` leaves `/plugin`:
    `view: (span) => { span.classList.add('x'); span.textContent = '★'; return {}; }`. A
    `component` becomes `view: svelteView(MathInline)`.
  - `DecorationWidgetSpec`: `buildDom: () => icon()` becomes
    `view: (target) => { target.append(icon()); return {}; }`, and `component: Ghost` becomes
    `view: svelteView(Ghost)`.
  - `InlineMenuSource.row`: a component becomes `svelteView(TagRow)`.
- **Upgrade note (Svelte hosts):** `Editor` and `EditorProps` come from
  `@voithos-labs/aragonite/svelte` now (`import { Editor } from '@voithos-labs/aragonite/svelte'`).
  The root's `EditorOptions` is every prop but `header`.
- **Upgrade note (plugin blocks):** a block kind is one registration now. Its view, and its opener
  if the parser has to recognize the syntax, go in the kind's own call, inside a plugin's setup:
  `definePlugin({ name: 'callout', setup: () => registerBlockKind('callout', { ...descriptor, view, opener }) })`.
  `registerBlockComponent`, `registerBlockOpener`, `definePluginBlock` and their `is*Registered`
  checks are gone.
  - A kind without a view doesn't compile, and from plain JavaScript it throws. Giving a view to a
    kind another plugin registered is a type error too (it never drew under that plugin anyway).
  - `defineBlockComponent(C, extra?)` is `svelteBlockView(C, extra?)` from `/svelte`, and
    `BlockComponentEntry` is the opaque `BlockView`. A view that isn't one (a component, a stub
    cast to `BlockView`) is refused with a message naming `svelteBlockView`.
  - No Svelte compiler in your app? `textBlockView({ blockClass? })` on `/plugin` is the editor's
    plain text block as a view.
  - An opener beside `contextDependentKind: true` is a type error now (it was a dev warning), and
    `augmentBlockKind` refuses `view`, `opener` and `contextDependentKind`.
  - `createEditableLeaf`, `createContainerBlock`, `BlockList` and their types, and `svelteView`
    import from `/svelte`.
- **Upgrade note (registering):** register and declare calls go in a `definePlugin` setup. Outside
  one (a module's top level, say), a dev build throws and tells you so; a production build doesn't
  check, so the call still runs there, it just isn't supported.
  - `isBlockKindDeclared`, `isBlockKindRegistered`, `isBlockCompleterRegistered`,
    `isPasteTransformRegistered`, `isLanguageRegistered` and `isInlineKindDeclared` left `/plugin`.
    A setup runs once per page, so nothing needs to ask. `isDirectiveRegistered` stays, for
    checking whether another plugin already claimed a `:::name`.
  - Registering a key that's already taken throws on a dev server too now, a built-in's key like
    `paragraph` included (it used to replace it quietly there). Saving an edit to a plugin under
    hot reload keeps the old definition and logs a warning, so reload the page to pick it up.
  - Tests on a runner other than Vitest call `configureEditorEnv({ isTest: true })` from
    `/testing`, which now also lets them register outside a plugin.
