# Changelog 0.12

Newest first; the index is [`../changelog.md`](../changelog.md).

### 0.12.0: plugins that can't half-write your document, and alerts that keep your spelling

- **A plugin that throws while you type no longer leaves a half-written document.** When a
  container's `rebuildRaw` throws on a keystroke, the key rolls back: the typed character
  disappears, `getSource()` is unchanged, and `error` fires with origin `commit` and `op: 'input'`.
  Before, the throw left the container half written and said nothing.
- **Alerts and footnotes keep the lines you didn't touch.** Type into a GitHub alert or a footnote
  definition and every other line stays as you spelled it (`>b` stays `>b`). Before, the first edit
  respelled the whole body.
- **Firefox stops reporting a ResizeObserver loop when you click into a long table.** A table that
  windows its rows could keep the height it was held at during load, and the next click let go of it
  in the middle of the browser's size reports. Firefox then fired "ResizeObserver loop completed
  with undelivered notifications" at `window.onerror`, which your error tracker probably saw too.
- **Tab in a text block undoes with the typing around it,** so one Ctrl+Z takes back both.
- **Changing a code block's language, committing a plugin's source, and cutting from a code block
  are each their own undo step.**
- **A keystroke's `edit` event fires inside the edit,** so a decoration source that invalidates from
  an `edit` handler re-runs a tick later, as it already did after every other edit.
- **A footnote's lazy lines read like a list item's.** A continuation line in a footnote definition
  indented less than four columns keeps its leading spaces as indent, not text. The file's bytes
  don't change and edits keep them, but the editor no longer draws those spaces, a plain-text copy
  leaves them out, and a plugin reading the definition's child `raw` sees the text without them.
- **New on `/plugin`: `rebuildStripRaw`, `quoteLines` and `hangingIndentLines`** (with `LineCodec`,
  `LinePlace` and `BodyLine`), for a container that puts a prefix on every line, so its rebuild keeps
  untouched lines byte for byte.
- **Upgrade note (plugin authors):** the container conformance kit's `declarations` cell now edits
  one child of your `deepNesting` fixture and fails when `rebuildRaw` rewrites any other line or
  drops the edited child's new bytes. A rebuild that re-emits the whole body fails it when your
  fixture is spelled differently from what the rebuild writes; `rebuildStripRaw` handles that for
  prefixed containers.
