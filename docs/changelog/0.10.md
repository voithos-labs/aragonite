# Changelog 0.10

Newest first; the index is [`../changelog.md`](../changelog.md).

### 0.10.5: inline menus and slash commands, a name for every block, Finn's behavior pass

- **A typed trigger opens a list under the caret.** `getInlineMenus()` on the instance (and
  `editor.inlineMenus` in a plugin's setup) takes `addSource({ name, trigger, items, onCommit })`:
  type `#`, `[[` or whatever the source claims, and a list opens with the rows the source hands
  back, synchronously or late. ArrowUp, ArrowDown, Enter, Tab and Escape work it while it shows,
  and a pick replaces the trigger and the query with one line of bytes in one undo entry; a block
  goes in through `onCommit` and `insertMarkdown`. The block reads as a combobox to a screen
  reader while the list is up. A duplicate row id or a pick that fails to write is reported on
  the `error` channel rather than thrown, a trigger typed inside a link's destination, a
  reference link's label or an image's alt opens nothing, and `open(name, { query })` opens a
  list from a button, already narrowed. Finn built it for limestone's wikilinks; the showcase's
  `#` tags run on it.
- **Slash commands ship as a bundled plugin.** `slashCommandsPlugin()` from
  `@voithos-labs/aragonite/plugins/slash-commands`: `/` at the start of a line or after a space
  lists every block the right-click "Insert block" menu offers, then Heading 1 to 3; typing
  narrows it, `/code js` opens a fence tagged `js`, `/table 3x4` makes a table that size, and
  `Mod+/` types the slash for you. `entries` adds rows of your own and `exclude` hides built-in
  ones. Under it sits one insert catalogue (`registerInsertEntry`, `getInsertCatalogue()`) that
  feeds the flyout and the list alike, so a plugin's block row shows up in both; the plugin
  context gained `insertMarkdown(md, { placement })` and `runCommand`, and a global command's
  handler now receives the argument `runCommand` was called with.
- **Every block has a name, and the keyboard reaches what only the mouse could.** A screen
  reader hears "Paragraph", "Heading level 2", "Code block" and "Divider" (a native `<hr>` now,
  not a slider); a table's first row announces as column headers; `Mod+Enter` checks or unchecks
  a task item (`list.toggleTask`); in reading mode a footnote marker and its definition's
  back-reference are links you can Tab to and press. A plugin kind names itself with `label` on
  its descriptor, and a title row with `label` on `registerChromeLeaf`: the bundled admonition
  title and details summary read "Title" and "Summary".
- **The light theme's greys clear AA.** `--color-ui-muted` reads `#676761` in the light theme
  and the dimmed markers sit at 0.68, so muted text and syntax markers pass 4.5:1 on the surface
  and the code fence. Finn's `--syntax-task-checked` and `--syntax-task-checked-tick` let a host
  colour a checked box and its tick.
- **A selected image and a document caret never coexist.** A third click on a selected image, a
  mouse move over it, or the caret the browser puts back on the next input used to leave a caret
  live beside the overlay; one listener drops it now. Home, End, PageUp and PageDown leave the
  image with the caret at its edge, the selection clears once its image is gone from the
  document, Shift+click extends from the image instead of the paragraph start, undo and redo
  pressed while an image is selected put the caret back at the image, a popover resize or
  removal restores the caret you had, and clicking a second image while the first one's alt
  field is open keeps the second one selected.
- **Undo puts the caret back where text arrived without a keydown.** Dictation, a soft keyboard
  and an IME commit land text with no keydown, and Ctrl+Z after them jumped the caret to the
  paragraph start. The pre-edit position is read at `beforeinput` now, which every input route
  fires.
- **Arriving into a paragraph full of widgets is quick.** ArrowDown into two hundred entities
  took a third of a second; the scan stops a few lines past its target and measures each widget
  once (361 to 54 ms on the widget-only fixture, 356 to 81 ms with a letter in front).
- **A source swap closes every menu and tells plugins.** Writing `source` with the block menu,
  the inline menu or the link card open left them over the new document, where a pick acted on
  it (and a swap under an open inline menu threw). They close first now. The edit channel fires
  `sourceSwap { generation }` and a plugin reads `editor.documentGeneration`; an unsaved alt
  draft from before the swap never lands in the new document.
- **`menuChange` counts every editor menu.** The table cell menu, the code rail and its language
  picker, the image properties popover and the link card report beside the block and inline
  menus, so a host that hides its own chrome while a menu is open gets one signal.
- **Finn's behavior pass.** The link card no longer sends the page to the top on Ctrl+K or the
  toolbar button, and it matches the menu and image chrome. A task item that became a heading
  showed a giant checkbox; the box sizes off the marker now. Heading styling waits for `#` plus a
  space, so a bare `#` doesn't flash. The caret behind an emoji doesn't flash larger before
  settling, and stays full height after one. A drag-select can start inside an emoji and from
  below the last block. The `+` beside the trailing row is gone; the invisible new-line button
  stays.
- **Selection and caret fixes.** A range across list items paints its box over the middle items
  too, and a cross-block selection paints once, not twice. Where an owned drag will drop, a caret
  shows, inside the range when you hold Control or Alt to copy instead of move. A click just
  below a picture inside its block seats a caret instead of swallowing the next key. Triple-click
  on an inline formula keeps its selection. In a live-mode code block, ArrowUp from below lands
  on the last body line. A cross-block range that starts inside a revealed one-line equation no
  longer deletes its closer. `selectionChange` is announced as the caret lands, ahead of the
  next input.
- **Live mode keeps a mark you emptied.** Deleting the last character inside `*x*` unwraps the
  pair, and the mark went with it, so the next Mod+I turned italic on instead of off; it stays
  pending now.
- **Bytes that reload as the tree you see.** Blanking a blockquote's or an alert's last
  paragraph, and a merge over a list holding a setext underline, left a document whose reload
  read different blocks; both keep their shape. A truncating write of a mermaid block puts its
  closing fence back. A pick from an inline menu on a blank line keeps the line's separators.
- **Block decorations reach list items.** A `block` decoration addressed at a list item paints
  its class, attributes and badge, the badge above the item's content.
- **`mailto:` and `xmpp:` addresses link.** `mailto:me@x.co` links whole the way cmark-gfm
  links it, and `xmpp` joins the allowed href schemes.
- **`reservedChords()` reports only what this editor dispatches.** An unlisted plugin's
  kind-keymap chords were in the set; the `plugins` prop filters them out now.
- **A backward selection restores backward.** `setSelection` and undo keep a single-block
  snapshot's direction, so a Shift+Arrow after the restore grows the end you expect.
- **A bare address inside a link's text stays text.** `[foo@bar.com](u)`, `[https://x.co](u)` and
  `[www.x.co](u)` parsed as a link holding an autolink and rendered an anchor inside an anchor;
  the bare-autolink scan skips a link's text now, both link forms, the way cmark-gfm does. An
  image's alt still links a bare address, which cmark-gfm does only for an email.
- **Block decorations reach table rows and cells, and can't replace what an element owns.** A
  `block` decoration addressed at a row or a cell paints its class and attributes (a badge is
  refused there: a row has no box of its own, and a cell's box is its editable text). And on every
  decorated element, `attrs` can no longer set `class`, `contenteditable`, `role`, `style` or
  `tabindex`: a `class` attribute wiped the element's own class and disposing left it classless.
  The decoration's `class` field is the road; each refusal gets the usual dev warning.
- **The kind checkup drives the raw-write rule.** `runKindConformance`'s report gains `rawWrite`: for
  every kind with a fixture it cuts the closing line and checks the next block survives, a kind
  that declares `normalizeRawWrite` also takes three truncating writes and must come back
  idempotent, and `exempt` now means the kind has neither a rule nor a top-level fixture. A fenced
  plugin kind that never declared the rule fails the checkup instead of passing it.
- **Admonitions and details say their names.** A screen reader hears "Admonition" and "Details"
  for those blocks, the way the built-in kinds got their names in this release.
- **Every grey the editor paints clears AA.** Muted text over a menu or the link card
  (`--color-ui-muted` is `#93938d` dark and `#62625c` light now), the light theme's dulled grey
  (`#5c5c56`), checked-task text, reference labels, blocked links and raw HTML (each with a grey of
  its own per theme, fainter than a quote but readable), and the reference definition block's fade
  (0.8, with the raw block's own fade stacked under it) all pass 4.5:1 on the surface, the code
  fence and the menu background. The contrast gate measures each where it paints, so a host that
  retunes its menu grey moves none of the others.
- **A task item's text is text, even when it starts with `#`.** `- [ ] # adwada` parsed as a
  to-do holding a level-1 heading. GFM says the marker starts the item's paragraph, so the rest of
  that line is plain text, and that's how the editor reads it now, on load and while you type. A
  heading on the next line inside the item is still a heading.
- **Two syntaxes a rendered view can't explain can be switched off per editor.**
  `syntax={{ indentedCode: false, setextHeading: false }}`: a line indented by a tab stays prose,
  and `---` under a line of text is a divider instead of turning the line into a heading. Only the
  reading changes; a file that holds either shape loads as prose, keeps every byte and saves as it
  came. Both are on by default, so the editor stays GFM unless you say otherwise. An editor's
  grammar now reaches inside list items, quotes and plugin containers too (a container plugin
  passes `grammar: ctx.grammar` to `parseContainerBody`), and a plugin left out of an editor's
  `plugins` prop has its block syntax read as plain Markdown there, instead of as a raw block with
  no component.
- **When a keystroke changes a block's kind, the editor says so.** In live and preview modes a
  typed edit that turns a paragraph into a code block or a heading shows the new kind's name at
  the block's corner for a moment and tells a screen reader once, so the change has a cause on
  screen. Commands and source mode show nothing.
- **A hidden hard line break shows a dimmed `↵`.** In the modes that hide markers, a backslash or
  two-space line break inside a paragraph left the next line hugging the previous one with no
  visible reason. A dimmed return mark sits where the break is now, outside the text, so the
  caret, copy and selection still see only the real bytes.
- **A CRLF to-do survives being emptied.** Emptying a task item in a CRLF document left its `\r`
  inside the marker, and the next keystroke wrote a lone carriage return that split the item on
  reload. The marker never takes a line ending now, and the item keeps its `\r\n`.
- **A plain Enter reads the editor's own grammar.** A split reparsed both halves with the global
  grammar, so it could make a switched-off code block, an unlisted plugin's block, or a heading
  inside a to-do. It reads the editor's grammar and the to-do's text now.
- **Swapping a small document for a huge one no longer mounts every block.** A `source` write
  that replaced a one-block document with a 2 MB one mounted all 78,000 blocks in one pass and
  froze the tab (the window was still the old document's, with windowing off). Each block list now
  decides whether to window from the children it receives, in the same pass, so the swap mounts
  one viewport's worth and returns in under half a second.
- **A block starts watching its height from the next frame.** A block mounted by a height
  correction used to start observing while the browser was still reporting sizes, which logged
  `ResizeObserver loop completed with undelivered notifications` on image loads and mode flips
  with content above the viewport. The watch starts on the next frame now; heights still land in
  the frame that measured them.
- **The `plugins` prop scopes everything a plugin registers.** A plugin an editor leaves out of
  its array used to keep reaching that editor through its inline syntax, its inline widgets, its
  directive names, its block completers, its paste surface and its auto-pairing, whatever the
  prop said. Each of those follows the prop now: the syntax stays text, a widget shows its source,
  a `:::name` the plugin claimed opens the generic directive box, a completer never fires, a paste
  into its block takes the default paste, and a trigger it auto-pairs stays a plain character. The
  shared `:::` and `::` directive kinds belong to the editor itself, whichever plugin turns
  directives on. Every edit that reparses (a merge, a reorder, an Enter completion, a range
  delete, the split) reads the editor's own grammar too, so an edit can't produce a kind the
  editor never listed, and bold or italic over plugin syntax the editor draws as text writes the
  bytes you'd expect instead of nesting a mark inside a mark. For plugin authors: `parseInline`
  takes an optional grammar, the grammar view answers `isPluginEnabled`, and the activation and
  grammar parameters the editor threads through its dispatch contexts are no longer nullable, so a
  caller can't answer `undefined`.
- **A slash pick, and any block insert from a menu, is one undo step.** A pick that inserted a
  block was three writes and three entries (the trigger removed, a paragraph inserted, the paste),
  so Ctrl+Z stepped back through an empty paragraph on its way. An inline-menu pick and the
  right-click flyout's insert are one entry each now. A source's `onCommit` may return a promise,
  and the join holds until it settles or until you type again, whichever comes first.
- **Breaking: `insertMarkdown` returns a promise.** `editor.insertMarkdown(md)` on the instance
  and on a plugin's editor context resolve to the boolean they used to return, once the insert has
  landed, so a pick can await the block it inserts. Under strict TypeScript an un-awaited
  `if (editor.insertMarkdown(md))` is a compile error now; in plain JavaScript it would read as
  always true, so add the `await`. `setSelection` already worked this way.
- **A list item or footnote body can end in an empty line.** Emptying the last paragraph inside a
  list item or a footnote definition left a tree the reload read differently, since a blank line
  carries no indentation to say it belongs inside. An indented blank line after a block is now
  the body's own empty paragraph, the first blank after a block is the separator, and the rebuild
  writes them back that way; a body whose separator line was indented gets it written bare on the
  first edit, the canonical spelling a container's own punctuation takes.
- **Pasting a block at the end of a paragraph, or into a cell, keeps the block whole.** Pasting
  `> q` after `abc` with `After` below turned `After` into part of the quote, and a block pasted
  into an empty table cell reloaded as different blocks. Every pasted block now lands with the
  blank line a reload needs, and its last line gets its own line ending.
- **A selected image reports where the editor will act.** `getSelection()` and the
  `selectionChange` payload report a collapsed caret at the image's edge (its end after a click)
  while an image is selected whole, where they reported nothing before; the next keystroke or
  `insertMarkdown` replaces the image there, and the undo entry records the same point. Restoring
  that value with `setSelection` puts a caret back without reselecting the image.
- **Smaller fixes.** A Shift+click from a selected image to the first character of a list item
  keeps its direction, so a following Shift+Arrow grows the end you expect. The image popover's
  byte shift is taken from what the commit wrote, not from the raw bytes, so a kind that
  normalizes its bytes follows the right offset. A `www.` or URL autolink inside an open bracket
  (an image's alt, an unclosed link) stays text, the way cmark-gfm reads it; the email form still
  links there. Two plugins that auto-pair the same trigger both get it paired; the editor
  remembered only the last one to register, so an editor listing just the first typed a plain
  character.
- **A plugin reads inline syntax the way its editor draws it.** `EditorContext.computeInlineContent(node)`
  parses a prose block in that editor's syntax, so whatever the `plugins` prop left out reads as
  text there too. A block component reaches it through `getEditor()` on the leaf and container
  factories (the owning plugin's `EditorContext`; `getOptions()` is shorthand for
  `getEditor()?.options`), and a component widget gets the same function as its
  `computeInlineContent` prop. Footnote numbers and toc labels read through it, so two editors
  over one document can number differently when only one of them lists latex. The free
  `computeInlineContent` is still there for code with no editor mounted, and it reads every
  installed plugin. `insertMarkdown` and `runCommand` on the context are declared as readonly
  properties now, like everything else on it; you call them the same way.
- **Link wrap, pending marks and edge typing follow the `plugins` prop too.** Mod+K over
  `:smile:` in an editor without emoji opens the link card now, a pending bold inside `$x$`
  without latex lands, and typing `:` at the end of a bold `:smile` stays inside the bold (it
  used to write `**:smile**:`). These checks read every installed plugin before; they read the
  editor's own list now.
- **A nested list guesses its heights at its own width.** A windowed list inside a quote or
  another list made its first height guesses at the scroll container's width, which is wider than
  the list, so its spacers were off until each item got measured. It guesses again once its own
  box exists.
- **Pasting before a line break keeps the rest of the paragraph.** Pasting two blocks, or a quote,
  at a soft or hard line break inside a paragraph deleted everything after the break. All of it
  stays now, wherever a reload would put it, and the same goes for list items pasted into a list
  item.
- **A tab indents the way CommonMark says it does.** A tab reaches the next multiple of four
  columns, so a tab-indented line under a list item belongs to that item and `\tcode` inside one is
  indented code. The file keeps its tabs on load and save; the first edit inside such an item can
  write that item's indentation back as spaces, and undo puts the tabs back.
- **Emptying the first item of a list under a paragraph keeps the list.** Find and replace emptying
  that item left a bare `-` under the paragraph, which is a setext underline, so the paragraph
  became a heading. The editor writes a blank line above the list now, the same one typing writes.
- **A plain line under a table is a row, and text you make there stays text.** GFM reads any line
  right under a table's rows that starts no other block as one more row, and so does the editor now
  (it used to end the table unless the line held a pipe). Unwrapping a quote or a list item right
  under a table, turning a heading into text there, or deleting the block in between used to hand
  the text to the table and lose your next key. The editor writes a blank line between them now,
  and the key lands in the paragraph.
- **Typing or pasting over a selected image puts the caret after the new text.** Typing `XY` over a
  selected image wrote `Y` at the paragraph's start. A typed key, Backspace, Delete, Ctrl+V,
  Ctrl+X and `insertMarkdown` over a selected image all land the caret after what they wrote, and
  an awaited `insertMarkdown` resolves with the caret already there.
- **A copied line's own line ending no longer splits your paragraph.** Pasting `x` plus its newline
  at the end of a paragraph, or right before a line break, added an empty line or split the
  paragraph. That one closing line ending is dropped now; a whole blank line at the end of what you
  copied still pastes.
- **A menu pick right after fast typing takes the whole query.** Typing `/quote` quickly and
  pressing Enter on a busy machine could pick before the menu had read the last keys, so `te` stayed
  behind as its own line above the quote. A pick reads the line first now.
- **Deleting a divider between a list and a quote reloads the same.** With blank lines around the
  divider, deleting it could leave the editor showing one block where a reload read two.
- **A pending mark works in a paragraph with a reference link.** In live mode, `Mod+B` then a key
  in a paragraph holding `[text][ref]` typed the character plain. It's bold now, and Backspace,
  Delete and typing at a reference link's hidden brackets read the link the way the screen does.
- **A paste into a CRLF document writes CRLF.** Pasting two paragraphs, or two lines, into a file
  with Windows line endings wrote the pasted lines with LF, so the file held both. Pasted lines
  take the ending of the line the caret is on, and a table split by a paste into a cell keeps its
  own.
- **Items pasted into an item keep the indented code after the caret.** That code landed on a new
  marker line, which a reload reads as a wider marker around plain text; it starts below an empty
  marker now, and so does a `---` line, which on a marker line is a divider ending the list.
- **After a paste or a Backspace, the caret stays with your text.** Pasting a quote before a line
  break put the caret after the line the quote took in, and a list pasted mid-paragraph put it
  after the text the list took in; it sits where the pasted text ends now. A Backspace whose
  joined line the block above then absorbed put the caret in the block below instead of at the
  join.
- **Bold across a reference link's edge writes nothing.** In a paragraph holding `[text][ref]`,
  `Mod+B` over a selection from inside the link's text to the end of the line wrote
  `see [te**xt][ref] here**`, asterisks that showed as literal text. The toggle reads the link the
  way the screen does now and writes nothing, as it always did beside an inline link. A `*` typed
  just before a `*` inside a reference link's text is written too, where it used to be skipped.
- **A marker typed in front of text keeps your place.** Typing `- `, `> `, `1. ` or `- [ ] ` at
  the start of `abcdef` sent the next key to the end of the line (`- abcdefQ`, `> abcdef Q`). It
  lands before the text now, and so it does when the item is typed under a list, when the quote
  is inside a list item, when a pasted space completes the marker, and when typing or pasting
  over a range from one block into the next does. The space after a bare `>` finishes the marker
  instead of landing in front of the text, and `[ ] ` typed at the start of an item's text keeps
  the caret before the text.
- **Indenting a paragraph under a list item puts it in the item.** Two spaces typed or pasted in
  front of `zz` in `- a\n\nzz` wrote `  zz`, which a reload reads as the item's second paragraph,
  while the editor kept it a paragraph of its own. The editor joins it to the item as the indent
  lands, for a bullet, an ordered item and either level of a nested list.
- **A paragraph joined into a long list's last item keeps the caret.** Under a list long enough
  that only part of it is drawn, indenting the paragraph below into the last item, or joining it
  to the item's text with Backspace, lost the caret, and the next key wrote nothing. The caret
  stays in the joined text now, in source and live mode.
- **A key typed between two tildes keeps both.** A space typed inside `~~b` wrote `~ b`, and
  Backspace there took both tildes, in every mode: the delimiter pairing read `~|~` as a pair it
  had written, and a tilde only ever pairs as `~~`. Both keys touch only their own byte now.
- **A paragraph's emptied last line takes the next key.** In source mode, erasing `more` from
  `Plan\nmore` left the caret on the empty second line, and the next key landed at the end of
  `Plan` instead. The empty line holds the caret now, as it already did in live mode.

### 0.10.4: the click ladder, a selection toolbar, and a drop that moves

- **A toolbar opens over a selection.** Select some prose and a small popover shows up beside it
  with bold, italic, strikethrough, inline code, a link button, a heading picker and copy. It's on
  by default and reading mode never shows it; pass `selectionToolbar={false}` if your app has a
  bar of its own, or the two will stack. The heading picker isn't offered when the selection spans
  blocks, and `runCommand('heading.cycle')` declines there instead of re-marking whichever block
  held the anchor. `TOOLBAR_COMMANDS.setHeading` publishes the id, so a host's own bar can grey the
  same button for the same reason.
- **Double-click takes the word, triple-click takes the block, and either can start a drag.** The
  browser used to own these, and its word rule depends on the platform (Windows grabs the space
  after the word), wanders into whatever formula or glyph sits next door, and paints before
  anything can correct it. The editor works the word out itself now: markers never count as part
  of it, an island beside it is never taken with it, and a triple-click selects the block's
  content, the same range the first Ctrl+A takes. Keep the mouse down on the second or third
  click and drag, and the selection grows a word or a block at a time, in either direction,
  inside the block and across blocks. A triple-click past the end of a line, or on the prose of a
  paragraph full of formulas, keeps what it painted instead of flashing and losing it.
- **Dragging a selection and dropping it moves the text, in one undo step.** The browser's own
  drop was two mutations the editor saw one at a time, so the dropped word snapped to the start
  of the paragraph and undo took two presses to put it back. The editor owns the drop now: the
  text lands where you released, out of a table cell too, and Ctrl+Z reverses the whole move at
  once. A drop the editor has no way to place is cancelled rather than handed to the browser,
  which used to guess.
- **Inline `$…$` math accepts a formula that opens with a digit.** `$10^5$` read as a price and
  rendered as text. A run that holds only a number (`$5$`, `$1,000$`) and the second price of
  `$10-$20` still read as currency, and a `$` claim ends at the next `$`, never reaching past
  prose into a later formula's closer. The closing rule is pandoc's; the price exception is ours.
- **A click on a rendered inline formula seats the caret where you clicked.** It opened the
  source with the caret at the end, the way the `$$` block did before 0.10.3. An inline widget
  kind maps a press to an offset through the new `revealOffsetAtPoint` editing-policy field.
- **The language picker lists each language once, and six more grammars ship.** The picker showed
  `rust` and `rs` as two rows; a language appears under its canonical name now and an alias is a
  search key that finds it (a typed alias still commits as typed, since it's the fence's own info
  string). A language's own name beats another language's alias when the two collide. csharp,
  kotlin, swift, php, powershell and dockerfile join the built-in set, and `getLanguageAliases`
  on the plugin barrel answers from any spelling, for a host building a picker of its own.
- **Vertical travel stops on a block that holds only a widget, once, in both directions.**
  ArrowDown into an image, a lone formula or a lone footnote reference entered it, and ArrowUp
  skipped it, so a run down and the run back up didn't retrace the same stops. One press enters
  the block now and the next moves on, whichever way you came. A paragraph holding only a
  decoded entity (`&copy;`) took three presses down and two up; it's one each way.
- **A caret beside a glyph, and a click past a run of them.** Clicking past a run of adjacent
  emoji, entities or inline images put the caret after the first one; it lands at the end of the
  run. A click on a glyph itself seats the caret at the edge nearer the press, the way a click
  beside one already did (images keep whole-widget select). And typing or Delete over a
  whole-block selection edits the selection even when the block opens with a formula or an
  emoji, instead of inserting beside the widget or taking the widget alone.
- **A block selected whole paints one box, chrome included.** A GitHub alert swept into a range
  had its title row left unpainted, since the row comes from the `[!NOTE]` marker and no child
  block covers it. A container takes its whole box now and its children take none.
- **Emptying a block equation leaves an empty body line, not bare delimiters.** Select-all and
  Backspace inside a `$$` block used to show the `$$` with nothing between. The block settles on
  an empty body line with the caret in it now, whatever emptied it, and typing resumes the
  formula. GitHub's ` ```math ` fence hides its fence lines on a marker-hiding rung the way
  the `$$` form does, and a delete beside them can't reach them.
- **A drag inside a mermaid diagram pans it, and opening its source doesn't scroll the page
  away.** Dragging to pan also painted the whole block as selected; it doesn't now, and a plugin
  block can declare `POINTER_GESTURE_ATTR` on any element whose drags are its own. Opening a
  diagram's source at the end of the document scrolled the page past the card; a container block
  can hold the reader's place across a view swap with the factory's `captureScrollPosition`.
- **The page holds still through a mode flip.** Flipping presentation mode slid the page by a
  pixel per re-measured block, and the first edit or undo after a flip jumped it. The editor's
  scroll corrections keep the fraction the scroller rounds away, and a structural rebuild keeps
  the heights it already measured instead of falling back to estimates.
- **Finn's smaller passes.** An image block shows a clear focus border with a matching resize
  handle (two accent colours in one place clashed). A list with a single item no longer shows a
  drag handle that had nothing to do. The task checkbox is square, and its hover area matches.
  And the selection wash, search-match and reorder tints fall back to fixed tints on engines
  without `color-mix` (Safari before 16.2), with `lh` fallbacks beside them for Safari before
  16.4.
- **Mermaid 12 is an accepted peer.** The `mermaid` peer range reads `^11.16.0 || ^12.0.0`.

### 0.10.3: finn's uiux once over

- **Every block answers a right-click now.** A context menu opens on the block under the pointer,
  carrying what that block can actually do. Right-clicking prose with nothing selected, or the
  `+` in the gutter, opens the block menu instead: lists, quote, divider, code, table, and math
  and notes wherever those plugins are installed. It is keyboard navigable, and it inserts at the
  caret rather than at the end of the document.
- **A trailing row sits under the last block.** A document that ends in a table or a code fence
  used to be a trap: there was nothing below to click, and the way out was an arrow key you had
  to know about. Clicking the trailing row adds a paragraph, and the `+` in its gutter opens the
  block menu.
- **The table menu folds into flyouts, and strips add a row or a column.** Insert and move
  gather into Row and Column groups that open on hover or on a key; delete and alignment stay
  where they were. Hovering a table's edge reveals an add-row and an add-column strip, which
  stay pinned while the caret is in the last row or column. The menu anchors to the click and
  rides with the content when the page scrolls, and a table edit no longer scrolls the page out
  from under you.
- **The table's grips are retired.** Rows and columns move by the cell menu and by Alt+Arrow,
  which both worked already and neither of which depends on hitting a two-pixel target. Ctrl+A
  in a cell now selects the cell, then the document.
- **A code block completes its own fence, and the language picker takes a host's list.** Typing
  ` ``` ` closes the fence at once, hides the backticks and opens the picker; a fence with no body
  yet completes when you focus it, and an unfocused empty one shows nothing at all. The rail
  beside the block is restyled and sits where it should, and a host can hand the picker the
  languages its app actually supports instead of taking ours.
- **Typing the closing fence on a code block's empty last line leaves the block.** It is how
  every other editor reads that run, and ours grew the fence to four backticks instead, on the
  reasoning that owns a fence typed anywhere else: a body line reading as the closer has to be
  escaped. On the empty last line it is the exit. None of the run reaches the document, the
  fence keeps the length it had, and the caret carries on in the block below.
- **Math blocks get three layouts and a source card that matches the code block's.** The card
  hides the `$$`, highlights the LaTeX and previews as you type, so the page stops reshuffling
  under every click. The toggle picks between the layouts, and the default is set per editor or
  baked into the plugin. An empty block keeps its fill and its height, a click seats the caret at
  the end, and inline math takes the same wash as inline code while its source is showing.
- **Undo inside an open source card steps back a burst of typing, not a character.** A math
  block's revealed source kept an undo history of its own that pushed an entry per keystroke, so
  Ctrl+Z crawled there where the same keys in a paragraph walked. It batches on the same pause
  the document uses now: a run of typing comes off in one press, and Enter, a paste or typing
  over a selection each stay a step of their own.
- **Images crop, and the alt text has a menu worth reading.** Image blocks are editable rather
  than decorative now: a crop that stays inside the image's own bounds, paste support in the
  demo, and an alt menu shaped like the rest of the editor's menus.
- **Inline delimiters pair themselves.** Typing one half of `**`, `_`, `` ` `` or a plugin's own
  syntax writes the twin behind the caret; typing the closer steps over it rather than doubling
  it, whether or not the closer is visible in the mode you are in; an empty pair collapses; and
  Backspace between the two halves takes both. A plugin opts its own syntax in through the
  inline-syntax registry.
- **Drag handles are on by default.** They show for the blocks a drag actually means something
  for, stay out of tables, and stay off text-like blocks where the gesture would fight with
  selecting words.
- **Task checkboxes match GitHub's.** The box sits at the margin, fills with the text colour,
  centres its tick, and does not shift the line when you toggle it. A done item dims instead of
  being struck through.
- **Two heading and list behaviors stopped being surprising.** Enter at the very start of a
  heading moves the heading down under a new line instead of splitting it, an empty heading
  demotes to a paragraph when you leave it, and Shift+Enter inside a list item paints a real
  new line rather than a backslash.
- **Drag-select can start in the margin.** A drag beginning beside the text now selects, within
  a block or across several, and releasing keeps what you selected. The overlay merges its rects
  per line, so a widget no longer gets painted over twice, and it re-measures when a block
  changes size under it.
- **A host is told when a menu opens.** The new `menuChange` event fires on the open and close
  of the editor's own menus, so app chrome, a floating toolbar above all, can step aside instead
  of overlapping. `runCommand` also takes an argument now, for commands that need one.
- **Bold and italic come off a selection that reaches past the word.** Selecting ` word` and
  pressing Ctrl+B wrote `**word**` with the space kept outside, since a run cannot close against
  whitespace, and the same selection pressed again did nothing: the unapply read the space as
  uncovered. The toggle now reads a selection through its boundary whitespace, so a second press
  strips what the first wrote, and a toolbar asking whether the mark is on gets the same answer.
  Styled source kept that space inside the delimiters, where no reader parses it as bold and the
  next press doubled them. Every mode wraps the word alone now, a code span included, which is
  what a press across several blocks always did.
- **A click on an equation puts the caret where you clicked.** Every click on a rendered `$$`
  block opened its source with the caret past the closing fence, so editing the head of a formula
  was a click and then a walk back through it. The press names a place in the equation now, and a
  click beside the ink takes the glyph nearest it. Arriving by keyboard is unchanged.
- **A block selected whole takes typing, paste and cut.** Dragging inside a rule or a rendered
  equation selects that block, and only Backspace acted on it: a character, a paste and a cut
  reached nothing, because the block holds no place for a caret and the keystroke landed on the
  editor itself. All four gestures go through the selection now: a character or a paste puts its
  own bytes where the block stood, a cut takes the block out and writes it to the clipboard, and
  each is one undo. A block emptied by any of them leaves no husk behind either: cutting an
  equation used to leave the blank line it stood on. Hosts reading `replaceBlock` see the source
  `cross-block-covered-block` where the whole-table paste reported `cross-block-paste-whole-table`.
- **The demo opens live and light.** It is the mode and the theme most people want first. The
  page is a full-width scroller with a centred column, so the document has room without the
  text running edge to edge.

### 0.10.2: an editor you can see on a white page

- **An editor with no theme of its own inherits the page's text color.** The root's text fell
  back to white whenever no host token and no `aragonite-editor-theme` wrapper set it, so the
  README's own snippet mounted white text on a fresh app's white page: you could type, and the
  spellcheck squiggle was the only sign you had. The fallback is `currentColor` now, so an
  unthemed editor reads in its page's own color, and the parrot's caption follows suit. The
  quickstart snippet gained the wrapper it always needed, saying `light` in both places that
  have to match the page.

### 0.10.1: large documents, the plugins prop, and a phone

- **A line that only becomes a heading with the line under it now joins it right away.** Pressing
  Enter in a heading standing above a bare `===` left two paragraphs on screen, though saving and
  reopening read them as one underlined heading. Any edit that puts a line directly above its
  `===` or `---` underline, or above a table's delimiter row, now folds the pair into the one
  block a reopen would show.
- **A format toggle across a giant table lands.** Selecting a table of tens of thousands of cells
  and pressing Ctrl+B did nothing at all: working out which cells the range covers handed every
  one of them to a single call, and past a certain count the engine refuses the call outright.
  The cells are gathered one at a time now, so the toggle writes, and a toolbar asking whether
  the format is already on gets an answer instead of an error.
- **A paste of a very large document lands.** Pasting more than about a hundred thousand blocks
  at once did nothing at all, for the same reason: every block went to a single call, and past a
  certain count the engine refuses the call outright. Each splice a document or a clipboard can
  scale now writes in bounded batches, so the paste lands, and so do a replace-all producing that
  many blocks and a fold over a container that wide.

- **The party parrot dances in CSS.** Its frames used to be swapped by a script timer that ran
  fourteen times a second whether or not the block was on screen, and the block's own text
  changed with every frame. All ten frames now sit in the DOM as one strip that CSS scrolls a
  frame at a time, so the dance costs no script, the bird's box stops resizing under it, and
  `prefers-reduced-motion` parks it on a single frame.

- **A plugin can say where a click lands in its own block.** `caretTargetAtPoint` was a
  descriptor field the editor read and no plugin could honestly fill: turning a press into a
  character offset means walking the DOM the way the caret does, and nothing on the plugin
  surface did it. `caretOffsetAtPoint` now does, taking one of your own elements and the press
  and answering the offset nearest it, with `CaretTarget` naming the shape the hook returns and
  `CURSOR_END` finally importable for a hook that means "wherever that leaf ends".

- **Enter works in a one-line plugin block.** Pressing it in a party parrot's caption used to
  type a newline the block had no way to show, so nothing appeared to happen. A leaf whose bytes
  are one line now says so with `createEditableLeaf`'s new `singleLine` option, and Enter ends
  the block the way it ends a heading: the text after the caret becomes a paragraph below, with
  the caret in it.
- **Decorations repaint on the keystroke that moved the text.** Marks, badges and islands
  followed the editor's batched edit event, which waits out a quarter-second typing pause, so
  an occurrence highlight visibly dragged behind the word it was painted over while you typed.
  Every decoration source now re-runs on each document change instead.
- **The occurrence highlight steps aside while you type.** Now that the marks keep up with the
  bytes, keeping up turned out to be the wrong thing to do: the word under your caret, and every
  copy of it on the page, lit up while you were still writing it. The marks clear on the first
  keystroke of a burst and come back a quarter-second after the last one, which is the editor's
  own typing pause rather than a timer the plugin brought along.
- **An editor runs only the plugins it was given.** The `plugins` prop is now the enablement
  set: an editor attaches the hooks, resolves the kinds, answers the commands and applies the
  paste transforms of exactly the plugins it lists, and a plugin another editor on the page
  installed does nothing here. Registration is still process-wide and still first-wins, and an
  editor mounted with no `plugins` prop still gets everything installed. This is how the demo
  keeps the occurrence highlight off until you ask for it: the toggle adds the plugin to the
  array.
- **A decoration source can invalidate itself from an edit handler.** `invalidate()` re-ran the
  source there and then, and an `edit` handler is called part-way through the commit that emitted
  it, so the source read a document the editor had not finished publishing. Such a call now waits
  for the commit, and several of them in one commit are one re-run. Everywhere else `invalidate()`
  stays synchronous.
- **A plugin's shortcut belongs to the editors that asked for it.** A global chord registered
  by any plugin on the page was swallowed by every editor on the page, so in an editor whose
  `plugins` array left that plugin out the key did nothing and reached neither the plugin nor
  the app around it. The chord now runs, is reported by `reservedChords()`, and is claimed by
  `claimsChord()` only in the editors that listed its plugin.
- **A paste reads the grammar of the editor it lands in.** Pasting into a paragraph, a code
  block or a table cell parsed the clipboard against every plugin installed in the process, so
  text written in a plugin's syntax became that plugin's block even in an editor whose `plugins`
  array left the plugin out, and the block then had no component to render it. Every paste route
  now parses through the same grammar the rest of that editor reads.
- **Footnote references and definitions jump to each other.** A plain click on a reference in
  reading mode, or Ctrl/Cmd+click while editing, lands the caret in the definition's body, and a
  click on the definition's `[^label]` marker lands it back after the first reference. Backspace
  at the start of a definition's body lifts that paragraph out of the note instead of doing
  nothing.
- **The party parrot ships as a bundled plugin.** `@voithos-labs/aragonite/plugins/parrot` is
  the plugin guide's quickstart, verbatim. Its caption is what you see at rest; the caret
  entering the block reveals the `%%parrot` line, and leaving it commits the edit as one undo
  entry.
- **The table's row and column grips follow `blockDragHandles`.** They painted whether or not
  the prop was on; now they show only when handles are on, like every other block's grip.
- **Typing inside a huge list or quote no longer slows down with the container.** A keystroke
  rewrites the one child's bytes inside its container's source instead of re-reading every
  child, so the cost tracks the block you are editing rather than the thousands around it. A
  25,000-item list was paying 17.7 ms per keystroke on a production build before this; it pays
  3.3 ms after, and a 250,000-item one 5.4 ms.
- **A party parrot scrolls in its own box.** The bird is wider than a phone column, and it used
  to take the whole document sideways with it, so a swipe right slid the text out from under the
  header. It scrolls itself now, the way a code block or a wide table already did.
- **Drag handles and table grips show up on a touch screen.** Both were revealed by hovering,
  which a finger never does, so `blockDragHandles` did nothing at all on a phone: the handle sat
  in the DOM permanently invisible. Where the pointer can't hover they now show at rest, and the
  grip itself takes the touch rather than the whole gutter beside it.
- **The find bar stays inside a narrow editor.** It was pinned to the right at a fixed width, so
  in a column much under 470px it ran off the left edge and the input couldn't be tapped at all.
  It now caps at the editor's width and wraps to a second row instead of overflowing.
- **Link and URL text is readable in both themes.** The accent color was one value serving a
  near-black editor and a white one, and it sat below the WCAG AA contrast line on the dark
  background and inside code blocks in either mode. It now carries a light and a dark value like
  every other color token, so links, URLs and the code fence's language label clear AA wherever
  they land. A host that declares `--color-accent` itself is unaffected.
- **Comments and keywords in a code block are readable on the fence.** The dark palette's Monokai
  pink and its comment grey both sat under the WCAG AA contrast line against the shaded background
  a code block paints behind them, and the light palette's comment grey missed it there too. All
  three keep their hue and clear AA now, on the editor surface and inside the fence.
- **Two costs paid once per block at load got cheaper.** Block identity comes off a counter
  rather than a UUID per block, and the height model seeds each block with fewer reads. Both scale
  with the block count of the whole document, which is what makes a 400,000-block load slow:
  3.2 s before, 2.0 s after, on a production build.
- **Backspace at the start of a directive's body lifts that paragraph out.** Pressed at the
  head of the first block inside a `:::name` container it did nothing at all: no bytes changed
  and the caret stayed put. It now lifts the block out above the container the way it does in a
  blockquote or a footnote, and the fences close over whatever body is left. A container whose
  first row is a title (the callouts, details) still declines the press, and now says so by
  name rather than by leaving a field out.

### 0.10.0: reload truth at every door, and windowing under host scroll

- **Host-scrolled documents window.** A page-scrolled shell (an app embedding the editor in
  its own scrolling page) now gets the same O(viewport) typing and mounting as a standalone
  editor: windowing reads a scrollport the scroll mode resolves, activation stays gated on the
  height budget alone, and a windowing editor withdraws its subtree from the host's native
  scroll anchoring and corrects by hand. `placeCaretAtPoint` below a windowed-out tail reveals
  the target before landing.
- **The live tree now converges with its own reload at every mutating door.** A demoted
  heading merges with the neighbours it stopped interrupting — above and below, with the caret
  following the typed byte; deleting an ordered list's first item folds the renumbered list
  into a tight paragraph above; a reorder, a nested edit, and a whole-body blank run under a
  callout all reload to exactly the shape they show. What a save writes is what a reopen reads.
- **A typed fence closes itself instead of swallowing the document.** Typing ` ```mermaid `,
  ` ``` `, or a math fence above other blocks mints the closing fence over an empty body; the
  blocks below stand. A gesture that merely exposes an existing open fence still folds, which
  is the reload's honest reading.
- **Whole-block kinds take AltGr, IME, and dead-key input.** A focused thematic break or
  diagram hosts a hidden editing surface on the gap caret's model, so composed and layout-mapped
  characters mint a paragraph instead of dropping; the tab order treats the block as one stop
  in each direction.
- **Footnote numbering costs the edited subtree, not the document.** With a reference mounted,
  the 1 MB keystroke p50 fell from 50 ms to 11.7 ms (100 KB: 8.2 to 4.1) by memoizing each
  top-level subtree's contribution against its bytes.
- **Three consumer doors.** `normalizeSelection` (document order over selection endpoints),
  `getBlockKindAt(path)` (the kind at a path, no DOM probing), and `canRunCommand(id)` (the
  dispatch seam's own admissibility, for greying a toolbar button) — resolved through the same
  tier walk the dispatch spends, so read and run cannot disagree. The demo toolbar rides all
  three.
- **Per-instance options reach plugin factories.** Leaf and container factories take a
  `getOptions()` thunk beside the block-command context's, and the bundled toc plugin reads its
  depth per instance, so two editors in one process render different depths.
- **Table cells follow the mode and theme.** A cell's inline widgets read the presentation
  mode and theme, and a mode flip rebuilds a cell's inline DOM the way it rebuilds a prose
  block's.
- **Paste fixes.** A pasted list ending in a table no longer takes a line ending inside the
  row; a clipboard's trailing blank line survives a paste at the document tail, in the
  document's own line-ending flavor.
- **A drag released on a whole-block kind ends there.** Releasing a selection drag over a
  thematic break or a diagram used to leave the endpoint in the block above, so the selection
  stopped short of what was highlighted; the hit test now answers with the block under the
  pointer.
- **A plugin container can declare its surface non-editable.** A container kind whose body is
  its own rendering, not text a caret belongs in, says so on its descriptor, and the editor
  treats it that way rather than making the author fake it.
- **The landable-caret guard covers every caret door.** G1.33 fires from the editor root's
  focus seam, so a plugin's own caret door and the render-primary reveal inherit the guard a
  built-in surface always had.
