# Changelog 0.10

Newest first; the index is [`../changelog.md`](../changelog.md).

### 0.10.8: typing that leaves your file's endings alone, and menus that close with the mode

- **Switching notes mid-typing doesn't switch you back anymore** (#683). `edit` fires for each
  keystroke as it's written, not once per burst after a quarter-second pause, so a host that
  loaded another note right after a key no longer got that held `edit` in the middle of the
  switch. Echoing `getSource()` into `source` from `edit` is safe now.
- **Anything still in flight when the host switches notes is dropped**, where it used to land in
  the new note: a paste waiting on the clipboard, a menu pick or slash command waiting on its
  commit, a formula or diagram with its source open, an empty heading being tidied. Undo and redo
  fire their `edit` as the document goes back, before the caret's placed.
- **Breaking for hosts:** you get one `edit` per key, so if you save on `edit`, debounce your own
  saves. `input` no longer carries `detail.byteLength`, and a key that changes its block's kind
  fires only `updateContent`.
- **Plugin API:** an inline menu's `onCommit` gets a third argument, an editor context scoped to
  its pick that writes nothing once the host has switched notes, so write through it. A slash
  row's `run` gets that context too (a new object, so not `===` the plugin's own; same members,
  read live, plus a `signal`), and may be async: it's awaited, so what it writes joins the pick's
  undo step. The context you close over in `onEditor` still writes into whatever note is open.
  New: `EditorContext.openDraft` for text a plugin holds outside the document, and
  `checkInlineMenuCommitAcrossSwap` on the testing subpath.
- **Writing `source` back with the text the editor already holds isn't a swap anymore** (#679).
  A host that keeps `source` in step from `edit` used to reload the document and wipe undo on
  every keystroke. It goes the other way too: writing back a text the editor has moved away from
  (the one it mounted with, say) now loads it, where before it quietly did nothing.
- **A file saved without a final line break stays that way** when you type in its last block
  (#616's typing half), toggle a format there, or edit a code block or a plugin block's source
  there. Each of those used to add one.
- **The cue that names a block's new kind shows for keys the editor types for you too**, like the
  second `*` the auto-pair adds, and it shows in code blocks and plugin blocks now.
- **A pair of stars you rebuilt yourself is yours** (#478). Put one back after deleting the
  auto-pair's, by typing or pasting, and typing inside keeps both. One used to vanish.
- **In a plugin block, typing over a selection that ends there replaces the whole selection**
  (#529), and the browser's own Undo is the editor's. Inside a shown source it steps through the
  source's edits first.
- **Pasting or cutting your way to a lone `$$` leaves it as text.** Press Enter to make the math
  block. Typing `$$` still makes one right away.
- **Undo puts the caret back where you were** after a word delete in live mode, a delete beside an
  emoji, or an empty heading tidied up when you leave it. It used to land a little early, or at
  the start of the line.
- **An HTML block retyped so it can't cut off the paragraph above joins that paragraph while you
  type** (#638), `<div>` to `<span>` under a line of text, say, the way a reload reads them.
- **Breaking an HTML comment's `-->` (or a `<pre>`'s closer, or retyping `div` as `pre`) lets the
  block swallow what's below it right away**, blank lines and all, like a reload does. Same for
  typing, pasting, and inside list items.
- **A paragraph that lands right under a link definition in one step and closes its two-line
  title becomes that title**, instead of staying a paragraph until the next reload.
- **Plugin API, breaking:** `readsFollowingLines` is gone from the block kind descriptor, replaced
  by `readingNotFinal` on `registerBlockOpener`, which means something else: given a block's own
  bytes, it answers whether more lines could still change how your opener reads them (an
  unclosed `$$` that turned into a paragraph says yes). A TypeScript registration that still sets
  `readsFollowingLines` won't compile, so delete the line; plain JavaScript just ignores it.
- **Editing a table changes only the rows you touch.** A tight `|a|b|` stays tight, `:--` stays
  `:--`, and moving a row or column, cycling an alignment, or pasting blocks into a cell leaves
  the rest of the table spelled the way your file had it. It used to respell the whole table to
  `| a | b |` on the first edit. A keystroke in a big table also copies one row for undo now,
  not all of them.
- **A row ending in `\|` reads its last cell the way GitHub does** (`x|`), and a cell you end
  with a backslash keeps a space before the next pipe, so the file reads the same everywhere.
- **Plugin API: `container.lastLineChild(node)`** says which child holds a container's last line,
  or -1 when the container's own bytes do. Leave it out and nothing changes. The container kit's
  `declarations` check now tests that answer, and its rebuild check covers grid kinds too, so a
  plugin grid whose `rebuildRaw` respells what it parsed fails it.
- **Moving a blank line to the top of an alert** (`> [!NOTE]` and friends) doesn't leave an extra
  empty block on screen anymore (#556), one the file didn't have after a reload.
- **Formatting across blocks got cheaper on long documents**, and so did deleting or pasting over a
  selection that starts inside a quote or a list. Each one used to save a copy of every block's
  bytes in case it had to back out halfway, which on a 25,000-block note is a lot of copying for
  something that basically never happens.
- **Switching modes closes every open menu.** The table's cell menu used to stay open when you
  switched to reading mode, still offering edits that reading mode then refused. Swapping the
  document through `source` closes them too.
- **An image's open alt field closes and keeps what you typed when you switch modes**, same as
  clicking away. When the host swaps in a new document the draft's dropped instead, so it can't
  end up in the wrong one.
- **Editing inside a quote or a list changes only the lines you edit.** Tabs stay tabs,
  `>b` stays `>b`, an indented list keeps its indent (typing in `  - a` doesn't nest the item
  below it anymore), and a lazy line, the paragraph continuation written with no `>` or indent,
  stays bare. The line you type on keeps its own prefix too, unless its indent cut a tab in half.
  Footnote definitions and alerts still respell their lines on the first edit.
- **A space typed right after a bare `>` goes straight into the quote's line**, as one undo step,
  so `>abcdef`, space, `Q` still gives `> Qabcdef`.
- **Type a heading over the line a lazy line was continuing** and that line keeps its bytes and
  leaves the quote or list, which is how a reload reads it.
- **Enter in a list item keeps the bytes of the lines it moves into the new item**, and a new item
  next to indented ones takes their indent.
- **Plugin API:** `rebuildRaw` may return `{ rereads: true }` to have the editor read its bytes
  whole afterwards. A rebuild that returns anything else (an expression-bodied
  `(node) => node.raw`, say) now fails the type check, so make it return nothing.
- **Typing over a table you selected whole replaces it with what you typed** (#558), and cutting
  it removes it, same as Backspace. Cutting a whole row or column removes it too, where it used to
  leave it there, empty.
- **Enter, Tab or Mod+digit over a table, row or column you selected whole removes it first**, then
  runs the key where the caret ends up, so it's Backspace and then the key, in one undo step.
- **Paste from a table cell's right-click menu replaces the selection** when one spans cells or
  blocks, the way Ctrl+V does. It used to paste into the cell you clicked and leave the selection
  painted.
- **An IME composition over a selection that spans blocks undoes in one step**, the delete and the
  composed text together.
- **Every key, cut, paste and composition over a selection across blocks puts the caret down the
  same way**, so a caret that ends up off screen scrolls into view after each of them.
- **Plugin API, breaking:** a block built on `createEditableLeaf` publishes everything the editor
  calls on it as one export, `export const blockApi = leaf.blockApi;`, in place of the eleven
  one-line re-exports (`focus`, `parkCaret`, ... `afterSourceCommit`). The leaf doesn't have those
  methods at its top level anymore, so the old re-exports stop compiling, and whatever the factory
  gains later reaches your block without an edit. Copying some of them out by hand, or exporting
  a partial `blockApi`, fails the type check or the lint.
- **Plugin API:** `leaf.getOptions<MyOptions>()` takes your options type, and with no editor
  mounted (a block mounted on its own in a test, say) it answers your plugin's `defaults`, so the
  `as` cast and the `?? default` fallback can go.
- **Plugin API:** `EditableLeafDeps` is split on `mode`, so a `render-primary` leaf without
  `isRevealed` or `setRevealed` is a type error, and a `plain` leaf can't pass them. Plain
  JavaScript still gets the clear error when the leaf is built.

### 0.10.7: a page that stays put, and a caret that lands where you meant

- **Near the bottom of a long document, a block that gets shorter doesn't throw the page up past
  where it should stop.** That's a diagram opening its source or a details block collapsing, say.
  The scroll drops by the height the block lost, and nothing more.
- **A host page that scrolls a windowed editor doesn't log a ResizeObserver loop error when the
  window resizes anymore.**
- **Something growing inside a list or a quote doesn't shove the page anymore**, whether it's an
  image decoding, a window resize or your own typing, and whether the container is above the
  screen or partly on it. The block you're reading (or the one your caret's in) stays put.
- **A table row that changes height without its text changing is measured again** (#546), a
  formula showing its source, say, so scrolling past it later doesn't jump by the difference.
- **Undo, redo and `setSelection` with an image selected put the caret where they meant to**
  (#673), instead of leaving the image selected and the caret gone. Same for an undo that brings
  back a caret between two blocks, like the one between a table and a code fence.
- **Ctrl+A with an image selected selects its paragraph.** Before, the image stayed selected, and
  typing replaced only the image.
- **Undo that brings a block back between the top of the screen and the line you were on keeps
  that line where it was.** Before, the restored block pushed it down.
- **Deleting a document's only block leaves an empty paragraph with the caret in it** (#563,
  #660), whether that block was a selected divider, a focused one, or a quote holding only a
  divider. It used to leave a document with no blocks at all. One undo brings the block back.
- **A quote, list or other container that a delete empties goes too**, and so does its parent if
  that empties next. Replacing a container's only block with nothing does the same, and Shift+Tab
  on a nested item that was its parent item's only content doesn't leave an empty item behind
  anymore: `- - a` gives `- a`.
- **Deleting a range that takes the whole document, or two closed details held whole, keeps the
  editor's block list in step with the document.** It used to come up one block short.
- **In live mode, pasting over a selection keeps the formatting typing over it would keep**
  (#542). Select the `a` in `**a** b`, paste `x`, and you get `**x** b`, same as if you'd typed
  it. The bold used to get dropped. Same in a list item and a table cell.
- **Pasting whole blocks over a selection in live mode cleans up the marks the cut leaves
  behind**, the way Delete does. Paste two paragraphs over the `a` in `***a***` and you get just
  the two paragraphs, not `***` lines around them. Same in a list item or a quote.
- **A pasted line in live mode doesn't push a hidden closer onto a new line anymore.** Paste `x`
  plus a line break over the `b` in `**ab**`, or right after it, and the closing `**` stays put.
  It used to land on its own line and show up as literal stars.
- **In live mode, deleting an entity, emoji, image or decoration that's alone inside bold takes
  the empty `**` with it.** Backspace after the © in `x **&copy;** y` gives `x  y`; it used to
  leave `x **** y`, stars and all. Same for Delete and for cutting a selected image.
- **Pasting over a selected image goes through the normal paste**, so pasted blocks land as
  blocks there too. It used to splice the clipboard text straight into the paragraph.
- **Backspace over a whole table, row or column works inside a quote, a list or a details block
  too** (#661), not just at the top level. It used to clear the cells and leave the table there.
  A selection between two table cells is the rectangle they span for every key, so from the
  top-right cell to the bottom-left one is the whole table, and Backspace removes it.
- **Copying a rectangle of table cells gives you that rectangle even after the table's scrolled
  out of view** (#565). It used to copy the whole rows. You get the same text and HTML table you'd
  get copying from inside the cell.
- **Select All in a document that's just one quote or one details block copies the whole thing**,
  markers and all, instead of only the text inside.
- **Formatting a range treats its ends the way copy and delete do.** A range ending on a closed
  details' title formats the hidden body too, and one starting partway into a plugin grid's cell
  starts where you started, not at the start of the cell.
- **Selecting from a divider at the top of a quote down into the next block and pressing
  Backspace takes the quote with it**, instead of leaving an empty `>` behind.
- **A drag that ends on a mermaid diagram highlights the whole diagram**, like any other block
  selected whole.
- **Undo after a paste puts the caret back where the paste began**, not where it ended, so the
  next key lands where you'd expect. Undoing a bold, italic, strikethrough or code toggle, or a
  code block indent or dedent, puts it back where the selection started too.
- **Picking from the slash menu or any inline menu, or editing a link card, doesn't yank your
  line to the top of the page anymore** (#489) once the new block measures in.
- **A search jump, `navigateTo` or a held `rects.scrollTo` keeps its target exactly where it
  landed** when something above it changes height, or the header resizes, instead of snapping it
  to the top of the viewport.
- **The caret doesn't get left off screen.** Undo and redo bring it back into view at the nearest
  edge, arrowing onto a paragraph, a table or the next table row just below the edge brings it on
  screen, and so does Select All then ArrowRight in a long document. In a paragraph taller than
  the window the page moves by a line, not a screenful. Arrowing onto a divider (or anything
  focused whole) comes in at the nearest edge too, not the middle.
- **Closing the find bar or the link card puts your caret back**, even when the search took you
  so far that the caret's block was unloaded. Focus used to fall to the page and the next key went
  nowhere. The view comes back to the caret at the nearest edge instead of centring it.
- **For plugin tests:** `installEditorDomStubsForTests` also stubs a text range's rects, which
  jsdom lacks, so a mounted editor's `setSelection` works there.
- **On Mac and Linux, a click, right-click, drag or Shift+click in the room above or below a
  line keeps the column you pointed at** (#671). That's a code block's grey box and the strip
  around it, a paragraph, a table cell, and a plugin's source. It used to snap to the start of
  the first line or the end of the last; only Windows got it right. Double and triple click, a
  tap and typing with an input method work from there the same as on the line.
- **In live mode, deleting, cutting, dragging or typing over a selection now cleans up the
  hidden `**` and `*` it cuts through in a list item's first paragraph, a to-do or a footnote**
  (#667), same as in a plain paragraph. Those leftover runs used to show up on screen.
- **Same in a table cell whose text starts with `# ` or `- `** (#523). Typing a delimiter at a
  hidden run in one of those cells gets its closing twin now, like in a paragraph, and so does a
  delimiter typed in a to-do whose text starts with `# `.
- **A space left at a list item's start counts toward its marker, the way a reload reads it.**
  Delete the `a` in `- a b` and the bytes are `-  b`: the editor used to keep a `- ` marker over a
  paragraph starting with a space, where a reload reads a three-space marker. Same for a to-do's
  checkbox, a numbered item and a list inside a quote. When the wider marker leaves a nested list
  or a second paragraph outside the item, the editor moves it out too, as the reload does, and undo
  puts it back. Since the space belongs to the marker now, Delete after that Backspace takes the
  `b`, and a second Backspace unwraps the item.
- **A quote that gains a `>` on its first line knows it's two deep**, whether you typed it or
  Backspace left it behind by lifting the quote's first block out.
- **Pasting a big spreadsheet grid into a long table lands the caret in the grid's last cell**
  (#547), even when that row wasn't on screen yet.
- **In live mode, Backspace on an empty code block lands the caret once**, at the end of the
  block above (#530). Two landings used to race between the blocks above and below.
- **Deleting a block you've selected whole puts the caret on the side the key points**, whether
  you clicked it or dragged a selection over it (a divider, say, or a whole table). Backspace
  lands at the end of the block above, Delete and cut at the start of the one below. Deleting
  from the block menu counts as Backspace. With nothing above and a list below, the caret goes
  into the list's first item, so typing lands there (#561).
- **Undo after typing over a divider you'd dragged across brings the divider back selected**
  (#603), so the next key replaces it again. It used to leave no selection at all.
- **A closed `<details>` stays closed when a selection or an undo reaches into it.** Collapsing
  or growing a selection past one, or undoing an edit inside it, puts the caret on its title row
  (#562). Search and the table of contents still open it, since there you asked to go inside.
- **`setSelection` on a block that holds other blocks** (a list, say) puts the caret in its first
  item, where typing goes, and a caret inside a closed `<details>` lands on its title row. The
  same goes for `navigateTo` at a container's path, except it opens a closed `<details>` on the
  way.
- **In live mode, clicking below a long document whose end is off screen** puts the caret after
  the last block's hidden closing `**`, same as below a short one.
- **Clicking or tabbing into the host's header and coming back forgets the column** an earlier
  Up or Down run held (#591), so the next arrow starts from where the caret is now.
- **Breaking for plugins: `updateOwnMetadata(patch, { caret: { path, offset } })`** replaces the
  `afterTick` callback. Say where the caret goes, relative to your block, and the editor puts it
  there once and scrolls it into view if it needs to.
- **Cutting a range that runs into a closed details copies what it deletes** (#636): the whole
  block, hidden body and all. The clipboard used to get a bare title with no body, or no markup
  at all for select-all over a lone closed details.
- **A range between a closed details and a table takes the whole details** (#659), from either
  end, like it already did next to plain text. The highlight paints the details as one box.
- **Text left in a to-do's first line reads the way a reload reads it.** A range delete joining
  `- [ ] a` with `- # b` keeps the checkbox in front of the text `# b` instead of making a heading
  a reload disagrees with (#639), and a plain item left starting with `[ ] ` becomes a to-do, as
  typing it does. The same goes for text dropped at a to-do's start (#662) and for a paste that
  splits a to-do's text (#666), including a single heading pasted at its start. When the text
  that's left turns into something other than a paragraph (a table, say), the checkbox goes, as
  it already did for typing and Backspace.
- **A lengthened fence stays lengthened** (#640). When a body line reads as the closer, the
  editor lengthens a mermaid or directive fence (three backticks to four, `:::` to `::::`), and
  the next edit used to shrink it back while a reload of the same bytes kept it long. The fence
  now stays as long as a reload reads it, including after you delete the line that forced it.
- **Adding or dropping the final line break keeps a fence's closing line in step.** A mermaid
  block or a directive at the end of a file with no final line break no longer rebuilds its
  closer with the wrong ending on the next edit.
- **Alt+ArrowUp and Alt+ArrowDown keep the moved block on screen** (#488). Once it crosses the
  editor's edge, the editor scrolls it back into view.
- **Enter, Backspace, list and move edits that land the caret off screen scroll it into view.**
  Enter at the very bottom of a long document, say.
- **In live mode, an end landing inside a list or quote puts the next character after the hidden
  `**`**, the same as at the top level (#548). Backspace on an empty list item used to leave the
  typed character inside the bold.
- **Breaking for plugins: a registry entry answers to one owner** (#651). Inline widgets and
  inline construct policies now belong to the plugin that declared the inline kind, the way a
  block kind's pieces always did, so a widget you register for someone else's inline kind shows
  wherever they're listed. A plugin that fills a slot on a built-in kind (a completer for
  `paragraph`, a widget for `emphasis`) owns that entry: it shows only in editors that list the
  plugin (it used to leak into every editor), and `resetPluginPlatformForTests()` drops it.
- **A block command you register on another plugin's kind runs as you.** `ctx.editor` is your
  `EditorContext`, so it reads your options, and a throw names you in the `error` event. A block
  component on a kind declared outside any plugin reads the plugin that registered it through
  `getEditor()` and `getOptions()`.
- **`augmentBlockKind` on a kind whose descriptor a plugin registered** only works from that
  plugin now; anyone could augment it before.
- **A plugin's inline read resolves reference links** (#641). `EditorContext.computeInlineContent`
  parsed without the document's link definitions, so the table of contents showed a heading's
  reference link raw (`See [docs][r]`) while the heading painted `See docs`. It reads the
  definitions as they stand at each call now, and hands out a new function when they change, so a
  plugin cache keyed on it refreshes.
- **A block added at the end of a file with no final line break is its own block** (#635). Enter
  at the end of the last list item, ArrowDown past the last block, and a click on the empty row
  under it used to glue the new block onto the last line, so a reload read one block where you'd
  made two.
- **A file with no final line break keeps it that way through structural edits.** Deleting the
  last block, Enter mid-line, a list exit, a paste at the end and a move all leave the last line
  unended. The one exception is an edit that leaves an empty block last, since that block is
  nothing but its line break. Typing still adds one for now.
- **Blocks that sit flush on the clipboard stay flush when pasted** (#554). A heading right over a
  paragraph used to land with a blank line between them; only the join with the text above gets
  one now.
- **Backspace at the start of a list item keeps the blank line before indented code** that moves
  up with it (#555), so the code no longer folds into the text on reload.
- **Backspace at the start of a quote's or alert's first paragraph keeps the blank line** between
  it and the rest of the quote (#557).
- **Redo after pasting over a whole table stops warning** (#602). The redo swapped the paragraph
  back in while the editor still held the old cell rectangle, so the selection toolbar read a
  rectangle against a paragraph and `selectionChange` heard about a selection that wasn't there.
  Undo and redo drop the old selection before the document changes now.
- **`setSelection` with plain numbers on a table selects cells.** An offset on a table's own path
  counts cells row by row from the header, so offsets 0 and 3 paint the rectangle between those two
  cells. It used to resolve `true` and select nothing.
- **Both corners of a cell rectangle say `cellCoordinate: true`** in `getSelection()` and
  `selectionChange`. Only the anchor used to, so a host had to check the block's kind as well.
- **A plugin grid whose cells hold only images stops the caret on ArrowUp and ArrowDown,** like a
  table does.
- **Live mode's hidden closers work the same inside a quote or list** (#552). Backspace out of a
  code block, say, put the caret at the end of the bold above it, and inside a quote the next letter
  landed inside the `**`. It lands after it now, like at the top level.
- **Moving the caret between blocks inside a long list or quote reaches a block that's scrolled out
  of the rendered window.** The editor mounts it first, like it already did at the top level,
  instead of skipping past it.
- **Undo in a far column of a wide table scrolls the table back to that cell,** so the caret lands
  somewhere you can see.
- **Breaking for plugins: a container publishes `childList()` instead of `revealByPath` and
  `getBlockComponentByPath`.** `ContainerBlockComponent` requires it, and it returns the new
  `ChildList` type from `@voithos-labs/aragonite/plugin`: how many children you have, their refs,
  and the window that mounts them. `createContainerBlock` builds it for you, so only a container you
  wrote by hand changes.
- **Breaking for plugins: a registration that pairs fields which can't work together is refused.**
  It's a compile error now, and `registerBlockKind` throws on the same pairs at runtime, so a plain
  JavaScript plugin or a cast doesn't slip past. A kind focused as one unit has to say
  `supportsInline: false` beside `blockFocus: 'whole-block'`, and it can't declare a content start
  or reserve a title row.
- **Breaking for plugins: `contentStart: { range, backspace? }` replaces `getContentRange` and
  `contentStartBackspace`.** The range is required, so a Backspace rule with nothing to act on won't
  compile.
- **A title row always keeps Backspace at its start.** Declaring `reservedChrome` means Backspace at
  the start of the title row keeps it, even without an `unwrapRole`. A title-row container with no
  `unwrapRole` used to hand that Backspace to the block around it, so the caret jumped up or an
  enclosing quote or list reshuffled. `'keep-reserved-chrome'` is gone from the vocabulary you write,
  and the published type is `ContainerUnwrapRole` (it was `UnwrapRole`).
- **Breaking for plugins: `augmentBlockKind` throws on a field fixed at registration**
  (`blockFocus`, `supportsInline`, `contentStart`, a container's `reservedChrome` and `unwrapRole`),
  from plain JavaScript too, where it used to overwrite them quietly.
- **`BlockKindDescriptor` is off `@voithos-labs/aragonite/plugin`.** It was the shape the editor reads
  back and nothing you write needs it; type against `BlockKindRegistration`.
- **The conformance kits check the kind you gave them** (#576). A cell used to pass on whatever node
  its fixture held, so a plugin grid's `localIndex` passed on the built-in table's check, and an
  inline `widget` cell could pass over built-in images. Each cell now finds a node of your kind where
  it looks, or fails naming what it found. A grid or `multiScope` cell the kit can't drive for your
  kind fails and tells you to declare it `boundary`.
- **Breaking for plugins: the three kits report a cell one way,** `{ cell, status, detail }`, with
  the statuses `asserted`, `exempt` and `boundary`. The kind kit's `column` is `cell`, `executed` is
  `asserted`, and `report.rawWrite` is a `rawWrite` cell at the end of `report.cells`; the container
  kit's `reason` is `detail`; `runInlineKindConformance` returns a promise. The testing entry exports
  `CellReport`, `CellStatus` and `KindCell` in place of the four old report types, and
  `KindCellContext` has no `descriptor`.
- **Plugins get `walkBlocks` and `blockNodeAt`** from `@voithos-labs/aragonite/plugin`: every block in
  document order with its path (`'skip'` leaves a block's children out, `'stop'` quits early), and
  the block at a path, or null.
- **An insert entry can take a word after it in the slash list.** Give it a `withArgument(word)` that
  returns the Markdown to insert, and `/name word` works for your block the way `/table 3x4` does.
- **Math redraws when you switch the editor's theme** (#243). The renderer you inject gets the theme
  too (`MathRenderer`'s options grew a `theme` field, and an adapter that ignores it still fits), and
  the cache keys on it, so a renderer that paints its own colors stops showing the old theme's drawing.
- **`latexPlugin()` doesn't need a renderer.** Without one, each formula shows its own source in the
  code font, with "Math renderer not configured" on hover, instead of a red error line. A formula the
  renderer actually rejects still shows red, with the parser's message on hover.
- **A malformed row in one editor's slash-commands options no longer knocks out its `/` menu.** The
  editor reports it and keeps the factory's rows.
- **Breaking for plugins: an editor's options land on your defaults one field at a time.** An
  editor's `{ plugin, options }` entry used to replace the factory's options wholesale, so
  `{ exclude: ['table'] }` dropped the rows you gave `slashCommandsPlugin({ entries })`. Now it keeps
  them (prob what you meant); pass `entries: []` to really have none. `editor.options` is never
  `undefined`: a plugin installed bare reads its `defaults`, so move an `editor.options ?? { … }`
  fallback into `defaults`.
- **Plugins declare `defaults` and `parseOptions`** on `definePlugin` and `definePluginBlock`. An
  editor's options land on top of `defaults` one field at a time; `parseOptions(raw)` returns the
  fields to keep, and a throw is reported on the `error` event while the plugin runs on its defaults.
- **Plugins get a renderer slot:** `createRendererSlot`, `createAsyncRendererSlot` and
  `renderSourceFallback` on `@voithos-labs/aragonite/plugin`. A slot is the one place an injected
  renderer lives; it caches per theme and gives you your fallback when the renderer is missing or
  throws. The bundled math and mermaid plugins are built on it.
- **Breaking for plugins: every prop an inline widget receives is typed as required** (the theme, the
  presentation mode, the document, the content version, `navigateTo`, `computeInlineContent`), and
  the editor decides each one's default once. A widget can call them directly instead of falling
  back to `'dark'` or `'source'` on its own; a test that mounts a widget by hand passes them.
- **``/code ja`va`` opens a `java` fence.** A backtick in the language gets stripped, the way the code
  block treats its info string; it used to open a fence with no language.

### 0.10.6: one copy of each rule

Never published on its own: it shipped as part of 0.10.7.

- **A kind change typed inside a list item or a quote undoes with the typing around it** (#471,
  #22). Backspacing through the `===` under a quoted title, or typing `# ` at the start of a list
  item, left the key that changed the block's kind as its own undo step, so the first Ctrl+Z put
  back only half of it. It's one press now, same as at the top level, and the caret goes back to
  where you started typing.
- **The `edit` channel counts that key too.** Inside a list item or a quote, a typing flush's
  `byteLength` now includes a last key that changed its block's kind, like it already did at the
  top level.
- **Finishing `> [!TIP]` in a quote keeps your caret.** Type the marker that turns a quote with
  text into an alert and the next key lands right after the `]`, not at the start of the block.
- **Erasing a setext underline inside a list item or a footnote keeps the emptied line in the item**
  (#618). Backspace through the `---` under `- Plan` left a line the reload read as the end of the
  item, so a second item turned into a second list. The line stays indented under its item now.
- **A block menu row is its own undo step.** "Replace with clipboard", "Dissolve into text" and a
  plugin's `replaceRaw` used to join the typing burst when you'd just typed in that block, so one
  Ctrl+Z took your typing with it. Now it undoes only the row, and the `edit` channel stops counting
  its bytes as typed input.
- **Lifting a block into a `<details>` body escapes a `</details>` line,** the way typing one does.
  Backspace at the start of a quote or list item sitting in a details body could lift a line that
  closed the details early.
- **A list paste that completes another block's syntax changes that block's kind,** the way typing
  the same bytes would (backticks that finish a code fence, say). The item used to keep a paragraph
  holding the fence's bytes, which a reload read as something else.
- **An inline popover in a `<details>` body decides whether anything changed from the bytes it
  would actually store,** escape included, so a no-op edit there adds no undo step.
- **"Replace with clipboard" writes the document's own line endings** (#633), and so does pasting
  over a selection that covers exactly one block. A Windows clipboard used to leave CRLF lines in an
  LF document, and an LF clipboard left LF lines in a CRLF one. A plugin's `replaceRaw` takes care
  of it too, and a plugin's paste transform always gets LF text.
- **A decoration source waits out an edit made from an `edit` handler.** A handler that
  committed an edit of its own and then called `invalidate()` ran the source at once, over a
  document the first edit had not finished writing. The source runs after both edits now.
- **`configureEditorEnv({ isDev: true })` turns on the invariant checks too.** A suite on a
  runner or bundler that resolves no export conditions was told to call it so warnings emit,
  but every invariant check stayed off, so the suite passed over violations its sink never
  heard of. The checks and the dev warnings now read one switch. The perf instruments read
  `isTest` the same way, instead of looking for Vitest themselves.
- **The container conformance kit runs under a DOM test environment.** `runContainerConformance`
  in a jsdom (or happy-dom) suite threw `effect_orphan` from its `localIndex` cell, which built a
  container's list state with no component around it. The kit's headless editor also normalizes
  selection endpoints the way the editor does, so a cell sees the endpoints a user's gesture makes.
- **Breaking for plugins: `registerBlockContextActions(kind, name, provider)` takes a name.**
  The name is unique per kind, and a second registration under it throws (a dev server replaces
  it, as every registry does). A plugin's context actions show only where the plugin is listed
  and stop stacking: an editor whose `plugins` prop leaves the plugin out no longer offers its
  rows, and a suite that resets between cases no longer sees one more copy of each row per case. A row that writes
  clipboard text runs it through `ctx.transformPaste(text)`, the paste transforms of that
  editor's plugins.
- **Breaking for plugins: `registerLanguage` throws on a taken name, and a plugin's code
  languages follow the `plugins` prop.** It's register-once like every other registry, where it
  used to quietly keep the first grammar; `isLanguageRegistered` is the check to make before
  registering. A language a plugin's setup registered highlights, and shows in the language
  picker, only in the editors that list the plugin.
- **The test reset clears everything a plugin registered.** `resetPluginPlatformForTests()`
  drops context actions and code languages too, highlighting included, so a case no longer
  inherits the first case's grammar, and it keeps the built-in paste surfaces it used to wipe.
  `applyPasteTransforms` on the testing subpath takes an optional list of plugin names, to run
  as an editor listing only those.
- **Breaking for plugins: a plugin whose setup threw resolves nowhere.** Its kind used to parse
  and render, its chords fire and its syntax read in any editor without a `plugins` prop, while
  its insert entry hid and its `onEditor` never ran. Now none of it resolves, in any editor.
- **An unlisted plugin's command does nothing.** `runCommand` with the id of a command from a
  plugin the editor leaves out returns `false` without running it or warning.
- **An edit at the end of a CRLF document keeps CRLF.** A document with Windows line endings
  and no final line break got an LF from any edit on its last line: typing, Enter, a paste, a
  table rebuilt there, a list exited there. The editor now reads the document's line ending once,
  from its first line break, and every line it writes takes it (#458).
- **Enter on the empty line above a code fence's closer leaves the block in a CRLF document**
  (#534), and "Dissolve into text" keeps CRLF, a lone fence opener included. Converting GitHub
  alerts keeps CRLF at an unterminated last line too.
- **A paste into a document holding both endings writes the document's first one.** It used to
  take the caret line's.
- **Plugins get the document's line ending.** A write rule's `ctx` and `BlockActionContext`
  both carry `lineEnding`, so a plugin's write rule or context action writes the ending the

- **An editor with a syntax switched off keeps its blocks apart through an edit.** With

  reload read it as a paragraph and a rule. Every read an edit makes now uses the editor's own
  grammar (#553).
- **Two plugin entry points take the grammar they read with.** `lineStartsOuterBlock`'s
  `OuterBlockScan.grammar` and `parseContainerBody`'s `grammar` option are required now: pass

- **Moving a block to or from the end of a document with no final line break keeps both lines.**

  quote. Both blocks keep their own lines now, and the document still ends without a line break

- **A caret the host or a menu places starts fresh.** After `setSelection`, the link card, the
  inline menu or a plugin's `navigateTo` put the caret somewhere, the next ArrowDown could still
  aim for the column an earlier Up or Down run remembered, and a pending bold from `Mod+B` could
  land on the next letter typed there. Those placements now drop that memory, the way a click
  does.
- **The keymap decides which chord is a block move.** The editor used to treat Alt+Arrow as a
  block move whatever the keymap said, so after a consumer rebound `block.moveUp` or
  `block.moveDown`, the new chord was read as an ordinary caret key and the freed Alt+Arrow
  wasn't. Now whatever chord runs a move leaves the caret's column and marker side alone until
  the move commits.
- **Reading mode refuses every write where the bytes are written.** Each commit, typing write
  and undo or redo declines in reading mode, so a block menu left open across a switch to
  reading can no longer delete its block (#517), and a replace there reports nothing replaced.
  A switch closes any open menu, and `insertMarkdown` answers `true` only when bytes moved. The
  switch itself counts as leaving the block the caret was in: an open edit is committed first,
  and an empty heading the caret sat in turns back into a blank line, so entering reading can
  now emit `edit`. A dev build warns `[aragonite:reading-write]` naming the write, the block's
  kind and what called it.
- **A math or mermaid fence doesn't eat the rest of the document anymore.** Find/replace or a
  range delete that left a ` ```math ` or ` ```mermaid ` block with a body line
  reading as its closer, or with its opener gone, used to open a fence over everything below it.
  Now the fence grows past that line, and a deleted opener takes its closer with it (#566).
- **A ` ```math ` block gets the same breathing room as a `$$` one** (#577).
- **You can edit a code block's fence lines wherever you can see them.** In source mode, and on
  the focused block in the preview modes, the ` ```js ` line is text like any other; live
  mode still keeps your edits off it, and a caret coming in from another block lands in the body.
- **Picking `math` as a live code block's language doesn't throw anymore.**
- **A kind's write rule has one shape.** `normalizeRawWrite` is now
  `rawWrite: { normalize, mapOffset }`, for a kind's own bytes, the same shape as a container's
  `bodyWrite` for a child's, and both get a `ctx` with the block (`node`), a `mode` and the
  document's `lineEnding`. A fenced plugin kind declares `fenceRawWrite(fenceShapeOfRaw)` and gets
  the built-in fence's rules for free. The fence reader (`matchFenceInfo`, `scanFence`,
  `fenceAnatomy`) and the code block's fence renderer are on the plugin entry too.
- **Every caret the editor places counts the bytes one way.** Where the fence lines are hidden,
  a caret can't land between an empty code block's two fence lines anymore (#572), and a code
  block or a plugin leaf now counts an inline widget by its source bytes when it reads or places
  the caret, the way prose blocks always did.
- **Drag handles follow one rule.** A setext heading shows none, same as a `#` heading (#518).
  A code block or an image inside an alert or a footnote gets one, the way it would inside a
  quote (#551). A paragraph of nothing but images (several images, a defined reference image, a
  linked image) gets the handle and the image menu (#519), and says "Copy images" or "Remove
  images" when there's more than one. A reference image with no definition shows as text, so it
  reads as prose now: no handle.
- **A lone `#` is announced as the paragraph it shows as**, not as "Heading level 1" (#521).
- **The tag menu stays out of a plugin widget's source**, so typing `#` inside a formula doesn't
  pop it open (#573).
- **A block decoration can't set the attributes the editor reads off a block.** Those are the 17
  `data-` names it looks up on a block's own element; a decoration that sets one loses it with a
  dev warning, and every other name is yours (#575).
- **Plugin containers get a container-sized height guess** before they're measured, so a long
  document full of alerts or footnotes stops jumping while you scroll.
- **A kind declares how it sits on the page.** New descriptor fields: `pageRole` (whether it

- **The kind conformance kit checks a write rule's caret too.** Its raw-write cell runs five

- **A gesture over a selection undoes in one press.** A paste, a typed character, Enter, Mod+digit

- **Dragging text no longer copies it when the cut fails to land.** If the cut half of a drop wrote
  nothing, the insert still ran, so the text showed up twice. Now the drop stops there.
- **Typing in a second editor on the page doesn't split an inline-menu pick's undo entry in the
  first one** (#520).
- **Tab on a list item that ends in a table lands at the start of the table's last cell,** not
  its end (#540).
- **Growing a selection past a closed details block doesn't open it.** Shift+Arrow and

- **Deleting a selection that covers any of a closed details block's summary row, or runs past
  it, removes the whole block,** hidden body included, the same as select-all does. A selection
  that only touches the row's first byte deletes nothing there (#601).
- **Deleting from an open details block's summary row into the block below leaves a block that

- **The caret lands where a block's write rule put the bytes,** on every route. A `|` typed in a

- **A closer-shaped line typed into a ` ```math ` block grows the fence** instead of splitting the
  block in two (#593).
- **Source mode shows a setext heading's underline,** and you can edit it like any other text

- **A formatting command, a heading change or Shift+Enter undoes on its own,** not together with
  the typing around it (#525).
- **A `$$` block's closer comes back on blur** if you delete it in the source, the way a code
  block's already did.
- **Plugin write rules see typing now.** A kind's `rawWrite` runs on every content write,
  including the user's typing, and gets `mode: 'authored'` there (`'literal'` when content

- **Replacing a selection in a live-mode code block keeps the block.** Typing, an emoji or other

- **A backtick typed or pasted onto a code fence's opener widens the fence by one.** In source

  the opener now (#596).
- **A table at the end of a file with no final line break stays that way.** Moving, adding or
  deleting a row or column, cycling an alignment, even typing in the last row, gave the file a
  line break it never had (#592).
- **Math fences on CRLF files work.** An empty ` ```math ` fence got a stray carriage return in its

- **ArrowDown on the last block in reading mode just stops.** It used to try adding a paragraph
  below, which reading mode refused (with a dev warning about it) (#606).
- **In the preview modes, pressing into a block lands where you pressed.** The block's markers
  and fence lines used to show up the moment it took focus, mid-press, which moved the text under
  the pointer and put the start of a drag somewhere else. They show up when you let go now (#608).
- **A click in the thin strip just above or below a code block puts the caret on its nearest
  line,** at the column you clicked, instead of nowhere (#609). The same goes for
  `placeCaretAtPoint` and a right-click at a point in a block's own padding.
- **A non-breaking space is text, not a blank** (#25). `#<NBSP>foo`, `-<NBSP>a`, `***<NBSP>` and
  a setext `===<NBSP>` stay paragraphs, the way GitHub renders them. A fence closer followed by
  one doesn't close the fence, and a bare link runs straight through one.
- **Enter doesn't eat a non-breaking space anymore.** A list item or quote line holding only one
  used to count as empty, so Enter left the list or quote and deleted it. Now it's content, and
  Enter starts the next item like it would anywhere else.
- **A table cell keeps a non-breaking space at its edge,** when another cell in the row is edited
  and when a copied table is pasted back in.
- **A thematic break, heading or fence closer on a last line ending in a lone `\r`** reads the
  way CommonMark reads it, instead of turning into a paragraph.
- **Plugins get `isBlankText`,** the blank test the editor itself uses (spaces, tabs and line
  endings only).
- **Backspace at the start of a list item joins it into a heading item above.** `- # Plan` or a
  title with `===` under it used to refuse the join and throw in the background. The underline
  stays under the title (#470).
- **A join inside a `<details>` body can't close it early.** If Backspace or Delete joins two
  lines into `</details>`, it's saved escaped, the same as typing or pasting it (#610).
- **A list-item join that completes another block turns into that block,** the way the same join
  already did outside a list (two backticks joined to a backtick and some text make a code fence).
- **Backspace on the last line of a file with no final line break doesn't add one.** Delete
  already left it alone.
- **A click in the margin beside a line inside a quote, list, alert, footnote or details body
  puts the caret on that line.** It used to place none, so the next key did nothing. A drag you
  let go of out there ends on that line too (#611).
- **In the preview modes, a tap on a touchscreen lands where you tapped,** like a mouse press
  already did (#612).
- **Rebinding or disabling `block.moveUp` / `block.moveDown` reaches blocks you select whole,**
  like a diagram. Alt+Arrow used to move them whatever you'd bound, and `runCommand` now moves a
  focused divider or plugin block too (#504).
- **Inside the open link card, whatever chord you've bound to `link.openCard` is swallowed,** not
  just `Mod+K`.
- **Ctrl+A twice selects the whole document with CapsLock on,** in paragraphs and code blocks
  too. Ctrl+Alt+A doesn't count as select-all anymore, which matches the table cell.
- **A mistyped chord in a kind's `keymap` throws when the kind registers,** in every build. It used
  to slip into production as a bare key that fired on every press.
- **`canRunCommand` stops saying yes to bold and friends on a plugin block with no text
  commands,** like a formula's source.
- **Breaking for plugins: `EditableLeaf.runCommand` is gone.** It only ever said no. If your
  component has `export const runCommand = leaf.runCommand`, delete the line.
- **Link reference definitions read their URL, title and label the way inline links do** (#567).
  `[foo]: /url "ti\"tle"` is a definition with the title `ti"tle`, `[foo]: /url\*` links to
  `/url*`, and `[foo]: <a<b>` stays text. A title or label can span lines, as CommonMark allows.
- **A heading's closing `#`s are drawn dimmed like the opening ones** (`# Title #`), and live mode
  hides them. Typing, Backspace, Shift+Enter, paste and the level chords at the end of the title
  keep them on the heading, and a tab after the opening `#`s isn't part of the text (#568).
- **A bare url or `www.` link ends at a `<`,** as on GitHub (#617). One right after another
  construct (an angle-bracket link, a code span) only links when a space or `(`, `*`, `_`, `~`
  comes first.
- **Copying table cells from a CRLF file copies CRLF rows,** and a pasted Markdown table splits into
  rows the way the editor reads tables.
- **Editing a link or resizing an image keeps entity-like text (`&copy;`) and a URL's parentheses
  as written.**
- **Plugin grammars read Markdown whitespace too** (directives, admonitions, math, footnotes), so a
  non-breaking space is text there. The plugin entry exports `isWhitespaceChar` and
  `trimWhitespace` for your own grammars.
- **`CodeRunRequest` has a required `language` field,** the fence's language as the code rail
  shows it. A test double that builds a request itself has to set it.
- **Pasting several blocks at the start of a heading's text keeps the heading** (#623). With the
  caret right before `Hi` in `# Hi`, pasting `abc\n\ndef` left an empty `# ` above the paste,
  which live mode then cleared, so the heading was just gone. Now the whole heading moves below
  the paste, the same way Enter there moves it down a line, and one undo takes it all back.

### 0.10.5: inline menus and slash commands, a name for every block, Finn's behavior pass

Never published on its own: it shipped as part of 0.10.7.

- **A typed trigger opens a list under the caret.** `getInlineMenus()` on the instance (and
  `editor.inlineMenus` in a plugin's setup) takes `addSource({ name, trigger, items, onCommit })`:
  type `#`, `[[` or whatever the source claims, and a list opens with the rows the source hands
  back, synchronously or late. ArrowUp, ArrowDown, Enter, Tab and Escape work it while it shows,
  and a pick replaces the trigger and the query with one line of bytes in one undo entry; a block
  goes in through `onCommit` and `insertMarkdown`. The block reads as a combobox to a screen
  reader while the list is up. A duplicate row id or a pick that fails to write is reported on
  the `error` channel rather than thrown, a trigger typed inside a link's destination, a
  reference link's label or an image's alt opens nothing, and `open(name, { query })` opens a
  list from a button, already narrowed. Finn built it for limestone's wikilinks; the showcase's
  `#` tags run on it.
- **Slash commands ship as a bundled plugin.** `slashCommandsPlugin()` from
  `@voithos-labs/aragonite/plugins/slash-commands`: `/` at the start of a line or after a space
  lists every block the right-click "Insert block" menu offers, then Heading 1 to 3; typing
  narrows it, `/code js` opens a fence tagged `js`, `/table 3x4` makes a table that size, and
  `Mod+/` types the slash for you. `entries` adds rows of your own and `exclude` hides built-in
  ones. Under it sits one insert catalogue (`registerInsertEntry`, `getInsertCatalogue()`) that
  feeds the flyout and the list alike, so a plugin's block row shows up in both; the plugin
  context gained `insertMarkdown(md, { placement })` and `runCommand`, and a global command's
  handler now receives the argument `runCommand` was called with.

  reader hears "Paragraph", "Heading level 2", "Code block" and "Divider" (a native `<hr>` now,

  a task item (`list.toggleTask`); in reading mode a footnote marker and its definition's
  back-reference are links you can Tab to and press. A plugin kind names itself with `label` on
  its descriptor, and a title row with `label` on `registerChromeLeaf`: the bundled admonition
  title and details summary read "Title" and "Summary".
- **The light theme's greys clear AA.** `--color-ui-muted` reads `#676761` in the light theme
  and the dimmed markers sit at 0.68, so muted text and syntax markers pass 4.5:1 on the surface
  and the code fence. Finn's `--syntax-task-checked` and `--syntax-task-checked-tick` let a host
  colour a checked box and its tick.
- **A selected image and a document caret never coexist.** A third click on a selected image, a
  mouse move over it, or the caret the browser puts back on the next input used to leave a caret
  live beside the overlay; one listener drops it now. Home, End, PageUp and PageDown leave the
  image with the caret at its edge, the selection clears once its image is gone from the
  document, Shift+click extends from the image instead of the paragraph start, undo and redo
  pressed while an image is selected put the caret back at the image, a popover resize or
  removal restores the caret you had, and clicking a second image while the first one's alt
  field is open keeps the second one selected.
- **Undo puts the caret back where text arrived without a keydown.** Dictation, a soft keyboard
  and an IME commit land text with no keydown, and Ctrl+Z after them jumped the caret to the
  paragraph start. The pre-edit position is read at `beforeinput` now, which every input route
  fires.
- **Arriving into a paragraph full of widgets is quick.** ArrowDown into two hundred entities
  took a third of a second; the scan stops a few lines past its target and measures each widget
  once (361 to 54 ms on the widget-only fixture, 356 to 81 ms with a letter in front).
- **A source swap closes every menu and tells plugins.** Writing `source` with the block menu,
  the inline menu or the link card open left them over the new document, where a pick acted on
  it (and a swap under an open inline menu threw). They close first now. The edit channel fires
  `sourceSwap { generation }` and a plugin reads `editor.documentGeneration`; an unsaved alt
  draft from before the swap never lands in the new document.
- **`menuChange` counts every editor menu.** The table cell menu, the code rail and its language
  picker, the image properties popover and the link card report beside the block and inline
  menus, so a host that hides its own chrome while a menu is open gets one signal.
- **Finn's behavior pass.** The link card no longer sends the page to the top on Ctrl+K or the
  toolbar button, and it matches the menu and image chrome. A task item that became a heading
  showed a giant checkbox; the box sizes off the marker now. Heading styling waits for `#` plus a
  space, so a bare `#` doesn't flash. The caret behind an emoji doesn't flash larger before
  settling, and stays full height after one. A drag-select can start inside an emoji and from
  below the last block. The `+` beside the trailing row is gone; the invisible new-line button
  stays.
- **Selection and caret fixes.** A range across list items paints its box over the middle items
  too, and a cross-block selection paints once, not twice. Where an owned drag will drop, a caret
  shows, inside the range when you hold Control or Alt to copy instead of move. A click just
  below a picture inside its block seats a caret instead of swallowing the next key. Triple-click
  on an inline formula keeps its selection. In a live-mode code block, ArrowUp from below lands
  on the last body line. A cross-block range that starts inside a revealed one-line equation no
  longer deletes its closer. `selectionChange` is announced as the caret lands, ahead of the
  next input.
- **Live mode keeps a mark you emptied.** Deleting the last character inside `*x*` unwraps the
  pair, and the mark went with it, so the next Mod+I turned italic on instead of off; it stays
  pending now.
- **Bytes that reload as the tree you see.** Blanking a blockquote's or an alert's last
  paragraph, and a merge over a list holding a setext underline, left a document whose reload
  read different blocks; both keep their shape. A truncating write of a mermaid block puts its
  closing fence back. A pick from an inline menu on a blank line keeps the line's separators.
- **Block decorations reach list items.** A `block` decoration addressed at a list item paints
  its class, attributes and badge, the badge above the item's content.
- **`mailto:` and `xmpp:` addresses link.** `mailto:me@x.co` links whole the way cmark-gfm
  links it, and `xmpp` joins the allowed href schemes.
- **`reservedChords()` reports only what this editor dispatches.** An unlisted plugin's
  kind-keymap chords were in the set; the `plugins` prop filters them out now.
- **A backward selection restores backward.** `setSelection` and undo keep a single-block
  snapshot's direction, so a Shift+Arrow after the restore grows the end you expect.
- **A bare address inside a link's text stays text.** `[foo@bar.com](u)`, `[https://x.co](u)` and
  `[www.x.co](u)` parsed as a link holding an autolink and rendered an anchor inside an anchor;
  the bare-autolink scan skips a link's text now, both link forms, the way cmark-gfm does. An
  image's alt still links a bare address, which cmark-gfm does only for an email.
- **Block decorations reach table rows and cells, and can't replace what an element owns.** A
  `block` decoration addressed at a row or a cell paints its class and attributes (a badge is
  refused there: a row has no box of its own, and a cell's box is its editable text). And on every
  decorated element, `attrs` can no longer set `class`, `contenteditable`, `role`, `style` or
  `tabindex`: a `class` attribute wiped the element's own class and disposing left it classless.
  The decoration's `class` field is the road; each refusal gets the usual dev warning.
- **The kind checkup drives the raw-write rule.** `runKindConformance`'s report gains `rawWrite`: for
  every kind with a fixture it cuts the closing line and checks the next block survives, a kind
  that declares `normalizeRawWrite` also takes three truncating writes and must come back
  idempotent, and `exempt` now means the kind has neither a rule nor a top-level fixture. A fenced
  plugin kind that never declared the rule fails the checkup instead of passing it.
- **Admonitions and details say their names.** A screen reader hears "Admonition" and "Details"
  for those blocks, the way the built-in kinds got their names in this release.
- **Every grey the editor paints clears AA.** Muted text over a menu or the link card
  (`--color-ui-muted` is `#93938d` dark and `#62625c` light now), the light theme's dulled grey
  (`#5c5c56`), checked-task text, reference labels, blocked links and raw HTML (each with a grey of
  its own per theme, fainter than a quote but readable), and the reference definition block's fade
  (0.8, with the raw block's own fade stacked under it) all pass 4.5:1 on the surface, the code
  fence and the menu background. The contrast gate measures each where it paints, so a host that
  retunes its menu grey moves none of the others.
- **A task item's text is text, even when it starts with `#`.** `- [ ] # adwada` parsed as a
  to-do holding a level-1 heading. GFM says the marker starts the item's paragraph, so the rest of
  that line is plain text, and that's how the editor reads it now, on load and while you type. A
  heading on the next line inside the item is still a heading.
- **Two syntaxes a rendered view can't explain can be switched off per editor.**
  `syntax={{ indentedCode: false, setextHeading: false }}`: a line indented by a tab stays prose,
  and `---` under a line of text is a divider instead of turning the line into a heading. Only the
  reading changes; a file that holds either shape loads as prose, keeps every byte and saves as it
  came. Both are on by default, so the editor stays GFM unless you say otherwise. An editor's
  grammar now reaches inside list items, quotes and plugin containers too (a container plugin
  passes `grammar: ctx.grammar` to `parseContainerBody`), and a plugin left out of an editor's
  `plugins` prop has its block syntax read as plain Markdown there, instead of as a raw block with
  no component.
- **When a keystroke changes a block's kind, the editor says so.** In live and preview modes a
  typed edit that turns a paragraph into a code block or a heading shows the new kind's name at
  the block's corner for a moment and tells a screen reader once, so the change has a cause on
  screen. Commands and source mode show nothing.
- **A hidden hard line break shows a dimmed `↵`.** In the modes that hide markers, a backslash or
  two-space line break inside a paragraph left the next line hugging the previous one with no
  visible reason. A dimmed return mark sits where the break is now, outside the text, so the
  caret, copy and selection still see only the real bytes.
- **A CRLF to-do survives being emptied.** Emptying a task item in a CRLF document left its `\r`
  inside the marker, and the next keystroke wrote a lone carriage return that split the item on
  reload. The marker never takes a line ending now, and the item keeps its `\r\n`.
- **A plain Enter reads the editor's own grammar.** A split reparsed both halves with the global
  grammar, so it could make a switched-off code block, an unlisted plugin's block, or a heading
  inside a to-do. It reads the editor's grammar and the to-do's text now.
- **Swapping a small document for a huge one no longer mounts every block.** A `source` write
  that replaced a one-block document with a 2 MB one mounted all 78,000 blocks in one pass and
  froze the tab (the window was still the old document's, with windowing off). Each block list now
  decides whether to window from the children it receives, in the same pass, so the swap mounts
  one viewport's worth and returns in under half a second.
- **A block starts watching its height from the next frame.** A block mounted by a height
  correction used to start observing while the browser was still reporting sizes, which logged
  `ResizeObserver loop completed with undelivered notifications` on image loads and mode flips
  with content above the viewport. The watch starts on the next frame now; heights still land in
  the frame that measured them.
- **The `plugins` prop scopes everything a plugin registers.** A plugin an editor leaves out of
  its array used to keep reaching that editor through its inline syntax, its inline widgets, its
  directive names, its block completers, its paste surface and its auto-pairing, whatever the
  prop said. Each of those follows the prop now: the syntax stays text, a widget shows its source,
  a `:::name` the plugin claimed opens the generic directive box, a completer never fires, a paste
  into its block takes the default paste, and a trigger it auto-pairs stays a plain character. The
  shared `:::` and `::` directive kinds belong to the editor itself, whichever plugin turns
  directives on. Every edit that reparses (a merge, a reorder, an Enter completion, a range
  delete, the split) reads the editor's own grammar too, so an edit can't produce a kind the
  editor never listed, and bold or italic over plugin syntax the editor draws as text writes the
  bytes you'd expect instead of nesting a mark inside a mark. For plugin authors: `parseInline`
  takes an optional grammar, the grammar view answers `isPluginEnabled`, and the activation and
  grammar parameters the editor threads through its dispatch contexts are no longer nullable, so a
  caller can't answer `undefined`.
- **A slash pick, and any block insert from a menu, is one undo step.** A pick that inserted a
  block was three writes and three entries (the trigger removed, a paragraph inserted, the paste),
  so Ctrl+Z stepped back through an empty paragraph on its way. An inline-menu pick and the
  right-click flyout's insert are one entry each now. A source's `onCommit` may return a promise,
  and the join holds until it settles or until you type again, whichever comes first.
- **Breaking: `insertMarkdown` returns a promise.** `editor.insertMarkdown(md)` on the instance
  and on a plugin's editor context resolve to the boolean they used to return, once the insert has
  landed, so a pick can await the block it inserts. Under strict TypeScript an un-awaited
  `if (editor.insertMarkdown(md))` is a compile error now; in plain JavaScript it would read as
  always true, so add the `await`. `setSelection` already worked this way.
- **A list item or footnote body can end in an empty line.** Emptying the last paragraph inside a
  list item or a footnote definition left a tree the reload read differently, since a blank line
  carries no indentation to say it belongs inside. An indented blank line after a block is now
  the body's own empty paragraph, the first blank after a block is the separator, and the rebuild
  writes them back that way; a body whose separator line was indented gets it written bare on the
  first edit, the canonical spelling a container's own punctuation takes.
- **Pasting a block at the end of a paragraph, or into a cell, keeps the block whole.** Pasting
  `> q` after `abc` with `After` below turned `After` into part of the quote, and a block pasted
  into an empty table cell reloaded as different blocks. Every pasted block now lands with the
  blank line a reload needs, and its last line gets its own line ending.
- **A selected image reports where the editor will act.** `getSelection()` and the
  `selectionChange` payload report a collapsed caret at the image's edge (its end after a click)
  while an image is selected whole, where they reported nothing before; the next keystroke or
  `insertMarkdown` replaces the image there, and the undo entry records the same point. Restoring
  that value with `setSelection` puts a caret back without reselecting the image.
- **Smaller fixes.** A Shift+click from a selected image to the first character of a list item
  keeps its direction, so a following Shift+Arrow grows the end you expect. The image popover's
  byte shift is taken from what the commit wrote, not from the raw bytes, so a kind that
  normalizes its bytes follows the right offset. A `www.` or URL autolink inside an open bracket
  (an image's alt, an unclosed link) stays text, the way cmark-gfm reads it; the email form still
  links there. Two plugins that auto-pair the same trigger both get it paired; the editor
  remembered only the last one to register, so an editor listing just the first typed a plain
  character.
- **A plugin reads inline syntax the way its editor draws it.** `EditorContext.computeInlineContent(node)`
  parses a prose block in that editor's syntax, so whatever the `plugins` prop left out reads as
  text there too. A block component reaches it through `getEditor()` on the leaf and container
  factories (the owning plugin's `EditorContext`; `getOptions()` is shorthand for
  `getEditor()?.options`), and a component widget gets the same function as its
  `computeInlineContent` prop. Footnote numbers and toc labels read through it, so two editors
  over one document can number differently when only one of them lists latex. The free
  `computeInlineContent` is still there for code with no editor mounted, and it reads every
  installed plugin. `insertMarkdown` and `runCommand` on the context are declared as readonly
  properties now, like everything else on it; you call them the same way.
- **Link wrap, pending marks and edge typing follow the `plugins` prop too.** Mod+K over
  `:smile:` in an editor without emoji opens the link card now, a pending bold inside `$x$`
  without latex lands, and typing `:` at the end of a bold `:smile` stays inside the bold (it
  used to write `**:smile**:`). These checks read every installed plugin before; they read the
  editor's own list now.
- **A nested list guesses its heights at its own width.** A windowed list inside a quote or
  another list made its first height guesses at the scroll container's width, which is wider than
  the list, so its spacers were off until each item got measured. It guesses again once its own
  box exists.
- **Pasting before a line break keeps the rest of the paragraph.** Pasting two blocks, or a quote,
  at a soft or hard line break inside a paragraph deleted everything after the break. All of it
  stays now, wherever a reload would put it, and the same goes for list items pasted into a list
  item.
- **A tab indents the way CommonMark says it does.** A tab reaches the next multiple of four
  columns, so a tab-indented line under a list item belongs to that item and `\tcode` inside one is
  indented code. The file keeps its tabs on load and save; the first edit inside such an item can
  write that item's indentation back as spaces, and undo puts the tabs back.
- **Emptying the first item of a list under a paragraph keeps the list.** Find and replace emptying
  that item left a bare `-` under the paragraph, which is a setext underline, so the paragraph
  became a heading. The editor writes a blank line above the list now, the same one typing writes.
- **A plain line under a table is a row, and text you make there stays text.** GFM reads any line
  right under a table's rows that starts no other block as one more row, and so does the editor now
  (it used to end the table unless the line held a pipe). Unwrapping a quote or a list item right
  under a table, turning a heading into text there, or deleting the block in between used to hand
  the text to the table and lose your next key. The editor writes a blank line between them now,
  and the key lands in the paragraph.
- **Typing or pasting over a selected image puts the caret after the new text.** Typing `XY` over a
  selected image wrote `Y` at the paragraph's start. A typed key, Backspace, Delete, Ctrl+V,
  Ctrl+X and `insertMarkdown` over a selected image all land the caret after what they wrote, and
  an awaited `insertMarkdown` resolves with the caret already there.
- **A copied line's own line ending no longer splits your paragraph.** Pasting `x` plus its newline
  at the end of a paragraph, or right before a line break, added an empty line or split the
  paragraph. That one closing line ending is dropped now; a whole blank line at the end of what you
  copied still pastes.
- **A menu pick right after fast typing takes the whole query.** Typing `/quote` quickly and
  pressing Enter on a busy machine could pick before the menu had read the last keys, so `te` stayed
  behind as its own line above the quote. A pick reads the line first now.
- **Deleting a divider between a list and a quote reloads the same.** With blank lines around the
  divider, deleting it could leave the editor showing one block where a reload read two.
- **A pending mark works in a paragraph with a reference link.** In live mode, `Mod+B` then a key
  in a paragraph holding `[text][ref]` typed the character plain. It's bold now, and Backspace,
  Delete and typing at a reference link's hidden brackets read the link the way the screen does.
- **A paste into a CRLF document writes CRLF.** Pasting two paragraphs, or two lines, into a file
  with Windows line endings wrote the pasted lines with LF, so the file held both. Pasted lines
  take the ending of the line the caret is on, and a table split by a paste into a cell keeps its
  own.
- **Items pasted into an item keep the indented code after the caret.** That code landed on a new
  marker line, which a reload reads as a wider marker around plain text; it starts below an empty
  marker now, and so does a `---` line, which on a marker line is a divider ending the list.
- **After a paste or a Backspace, the caret stays with your text.** Pasting a quote before a line
  break put the caret after the line the quote took in, and a list pasted mid-paragraph put it
  after the text the list took in; it sits where the pasted text ends now. A Backspace whose
  joined line the block above then absorbed put the caret in the block below instead of at the
  join.
- **Typing into a setext heading keeps its underline.** The `===` or `---` under a title is drawn
  in no mode, and the first key typed into the title dropped it, so the heading became a paragraph.
  Erasing the whole title still takes the underline with it, and now so does cutting the title or
  pasting only spaces over it, which left the underline behind as a divider or a `===` paragraph.
- **Joining into a setext heading works in every mode.** Delete at the title's end and Backspace
  from the block below put the joined text on the title line, above the underline, and ArrowRight
  at the title's end moves on to the next block. A range delete that starts in a setext heading
  keeps its underline; one that ends in a setext heading drops that heading's underline.
- **A table row wider than its header keeps its extra cells.** GFM shows only the header's column
  count, and the first edit anywhere in the table used to drop the rest. They stay in the file now
  (source mode doesn't show them yet, #464), and a wide row that becomes the header widens the
  table.
- **A table ends where the editor's own grammar says.** A `$$` math block right under a table
  loads as math rather than more rows, and an indented line counts as a row when indented code is
  switched off.
- **Deleting a divider above indented code keeps every byte.** Deleting the divider between a
  paragraph and indented code with whitespace lines lost a blank line, or left the editor showing
  blocks a reload didn't.
- **Two new read-only fields for plugin authors.** `OuterBlockScan.window` holds the lines around
  the one an opener is asked about, and `TableRowMetadata.surplusCells` holds a row's cells past
  the header's count.
- **Bold across a reference link's edge writes nothing.** In a paragraph holding `[text][ref]`,
  `Mod+B` over a selection from inside the link's text to the end of the line wrote
  `see [te**xt][ref] here**`, asterisks that showed as literal text. The toggle reads the link the
  way the screen does now and writes nothing, as it always did beside an inline link. A `*` typed
  just before a `*` inside a reference link's text is written too, where it used to be skipped.
- **A marker typed in front of text keeps your place.** Typing `- `, `> `, `1. ` or `- [ ] ` at
  the start of `abcdef` sent the next key to the end of the line (`- abcdefQ`, `> abcdef Q`). It
  lands before the text now, whether the item goes under a list, the quote sits in a list item, a
  pasted space finishes the marker, or you type or paste over a range that spans two blocks. The
  space after a bare `>` finishes the marker
  instead of landing in front of the text, and `[ ] ` typed at the start of an item's text keeps
  the caret before the text.
- **Indenting a paragraph under a list item puts it in the item.** Two spaces typed or pasted in
  front of `zz` in `- a\n\nzz` wrote `  zz`, which a reload reads as the item's second paragraph,
  while the editor kept it a paragraph of its own. The editor joins it to the item as the indent
  lands, for a bullet, an ordered item and either level of a nested list.
- **A paragraph joined into a long list's last item keeps the caret.** Under a list long enough
  that only part of it is drawn, indenting the paragraph below into the last item, or joining it
  to the item's text with Backspace, lost the caret, and the next key wrote nothing. The caret
  stays in the joined text now, in source and live mode.
- **A key typed between two tildes keeps both.** A space typed inside `~~b` wrote `~ b`, and
  Backspace there took both tildes, in every mode: the delimiter pairing read `~|~` as a pair it
  had written, and a tilde only ever pairs as `~~`. Both keys touch only their own byte now.
- **A paragraph's emptied last line takes the next key.** In source mode, erasing `more` from
  `Plan\nmore` left the caret on the empty second line, and the next key landed at the end of
  `Plan` instead. The empty line holds the caret now, as it already did in live mode.
- **Moving a block keeps apart blocks a blank line kept apart.** Moving away the paragraph
  between a `<div>` block and a quote left the two flush, and the quote and everything under it
  down to the next blank line reloaded as HTML text; a table, a picture or a divider under a
  paragraph, or a quote under a quote, was taken in by the block above the same way, in the
  document and inside a quote alike. Where a blank line separated either block from the one that
  moved, the move keeps one between them now, in the same undo step, for the chord and a handle
  drag alike.
- **A key between two delimiters you typed keeps both.** Typing `**b`, then a space between the
  two stars, lost a star, and Backspace there took both; `__b` and `$$b` did the same. The
  auto-pair now remembers the pair it wrote and treats only that pair as its own, so its own pair
  still steps over, drops its partner and goes whole on Backspace, even after you type inside it
  and delete that again.

### 0.10.4: the click ladder, a selection toolbar, and a drop that moves

- **A toolbar opens over a selection.** Select some prose and a small popover shows up beside it
  with bold, italic, strikethrough, inline code, a link button, a heading picker and copy. It's on
  by default and reading mode never shows it; pass `selectionToolbar={false}` if your app has a
  bar of its own, or the two will stack. The heading picker isn't offered when the selection spans
  blocks, and `runCommand('heading.cycle')` declines there instead of re-marking whichever block
  held the anchor. `TOOLBAR_COMMANDS.setHeading` publishes the id, so a host's own bar can grey the
  same button for the same reason.
- **Double-click takes the word, triple-click takes the block, and either can start a drag.** The
  browser used to own these, and its word rule depends on the platform (Windows grabs the space
  after the word), wanders into whatever formula or glyph sits next door, and paints before
  anything can correct it. The editor works the word out itself now: markers never count as part
  of it, an island beside it is never taken with it, and a triple-click selects the block's
  content, the same range the first Ctrl+A takes. Keep the mouse down on the second or third
  click and drag, and the selection grows a word or a block at a time, in either direction,
  inside the block and across blocks. A triple-click past the end of a line, or on the prose of a
  paragraph full of formulas, keeps what it painted instead of flashing and losing it.
- **Dragging a selection and dropping it moves the text, in one undo step.** The browser's own
  drop was two mutations the editor saw one at a time, so the dropped word snapped to the start
  of the paragraph and undo took two presses to put it back. The editor owns the drop now: the
  text lands where you released, out of a table cell too, and Ctrl+Z reverses the whole move at
  once. A drop the editor has no way to place is cancelled rather than handed to the browser,
  which used to guess.
- **Inline `$…$` math accepts a formula that opens with a digit.** `$10^5$` read as a price and
  rendered as text. A run that holds only a number (`$5$`, `$1,000$`) and the second price of
  `$10-$20` still read as currency, and a `$` claim ends at the next `$`, never reaching past
  prose into a later formula's closer. The closing rule is pandoc's; the price exception is ours.
- **A click on a rendered inline formula seats the caret where you clicked.** It opened the
  source with the caret at the end, the way the `$$` block did before 0.10.3. An inline widget
  kind maps a press to an offset through the new `revealOffsetAtPoint` editing-policy field.
- **The language picker lists each language once, and six more grammars ship.** The picker showed
  `rust` and `rs` as two rows; a language appears under its canonical name now and an alias is a
  search key that finds it (a typed alias still commits as typed, since it's the fence's own info
  string). A language's own name beats another language's alias when the two collide. csharp,
  kotlin, swift, php, powershell and dockerfile join the built-in set, and `getLanguageAliases`
  on the plugin barrel answers from any spelling, for a host building a picker of its own.
- **Vertical travel stops on a block that holds only a widget, once, in both directions.**
  ArrowDown into an image, a lone formula or a lone footnote reference entered it, and ArrowUp
  skipped it, so a run down and the run back up didn't retrace the same stops. One press enters
  the block now and the next moves on, whichever way you came. A paragraph holding only a
  decoded entity (`&copy;`) took three presses down and two up; it's one each way.
- **A caret beside a glyph, and a click past a run of them.** Clicking past a run of adjacent
  emoji, entities or inline images put the caret after the first one; it lands at the end of the
  run. A click on a glyph itself seats the caret at the edge nearer the press, the way a click
  beside one already did (images keep whole-widget select). And typing or Delete over a
  whole-block selection edits the selection even when the block opens with a formula or an
  emoji, instead of inserting beside the widget or taking the widget alone.
- **A block selected whole paints one box, chrome included.** A GitHub alert swept into a range
  had its title row left unpainted, since the row comes from the `[!NOTE]` marker and no child
  block covers it. A container takes its whole box now and its children take none.
- **Emptying a block equation leaves an empty body line, not bare delimiters.** Select-all and
  Backspace inside a `$$` block used to show the `$$` with nothing between. The block settles on
  an empty body line with the caret in it now, whatever emptied it, and typing resumes the
  formula. GitHub's ` ```math ` fence hides its fence lines on a marker-hiding rung the way
  the `$$` form does, and a delete beside them can't reach them.
- **A drag inside a mermaid diagram pans it, and opening its source doesn't scroll the page
  away.** Dragging to pan also painted the whole block as selected; it doesn't now, and a plugin
  block can declare `POINTER_GESTURE_ATTR` on any element whose drags are its own. Opening a
  diagram's source at the end of the document scrolled the page past the card; a container block
  can hold the reader's place across a view swap with the factory's `captureScrollPosition`.
- **The page holds still through a mode flip.** Flipping presentation mode slid the page by a
  pixel per re-measured block, and the first edit or undo after a flip jumped it. The editor's
  scroll corrections keep the fraction the scroller rounds away, and a structural rebuild keeps
  the heights it already measured instead of falling back to estimates.
- **Finn's smaller passes.** An image block shows a clear focus border with a matching resize
  handle (two accent colours in one place clashed). A list with a single item no longer shows a
  drag handle that had nothing to do. The task checkbox is square, and its hover area matches.
  And the selection wash, search-match and reorder tints fall back to fixed tints on engines
  without `color-mix` (Safari before 16.2), with `lh` fallbacks beside them for Safari before
  16.4.
- **Mermaid 12 is an accepted peer.** The `mermaid` peer range reads `^11.16.0 || ^12.0.0`.

### 0.10.3: finn's uiux once over

- **Every block answers a right-click now.** A context menu opens on the block under the pointer,
  carrying what that block can actually do. Right-clicking prose with nothing selected, or the
  `+` in the gutter, opens the block menu instead: lists, quote, divider, code, table, and math
  and notes wherever those plugins are installed. It is keyboard navigable, and it inserts at the
  caret rather than at the end of the document.
- **A trailing row sits under the last block.** A document that ends in a table or a code fence
  used to be a trap: there was nothing below to click, and the way out was an arrow key you had
  to know about. Clicking the trailing row adds a paragraph, and the `+` in its gutter opens the
  block menu.
- **The table menu folds into flyouts, and strips add a row or a column.** Insert and move
  gather into Row and Column groups that open on hover or on a key; delete and alignment stay
  where they were. Hovering a table's edge reveals an add-row and an add-column strip, which
  stay pinned while the caret is in the last row or column. The menu anchors to the click and
  rides with the content when the page scrolls, and a table edit no longer scrolls the page out
  from under you.
- **The table's grips are retired.** Rows and columns move by the cell menu and by Alt+Arrow,
  which both worked already and neither of which depends on hitting a two-pixel target. Ctrl+A
  in a cell now selects the cell, then the document.
- **A code block completes its own fence, and the language picker takes a host's list.** Typing
  ` ``` ` closes the fence at once, hides the backticks and opens the picker; a fence with no body
  yet completes when you focus it, and an unfocused empty one shows nothing at all. The rail
  beside the block is restyled and sits where it should, and a host can hand the picker the
  languages its app actually supports instead of taking ours.
- **Typing the closing fence on a code block's empty last line leaves the block.** It is how
  every other editor reads that run, and ours grew the fence to four backticks instead, on the
  reasoning that owns a fence typed anywhere else: a body line reading as the closer has to be
  escaped. On the empty last line it is the exit. None of the run reaches the document, the
  fence keeps the length it had, and the caret carries on in the block below.
- **Math blocks get three layouts and a source card that matches the code block's.** The card
  hides the `$$`, highlights the LaTeX and previews as you type, so the page stops reshuffling
  under every click. The toggle picks between the layouts, and the default is set per editor or
  baked into the plugin. An empty block keeps its fill and its height, a click seats the caret at
  the end, and inline math takes the same wash as inline code while its source is showing.
- **Undo inside an open source card steps back a burst of typing, not a character.** A math
  block's revealed source kept an undo history of its own that pushed an entry per keystroke, so
  Ctrl+Z crawled there where the same keys in a paragraph walked. It batches on the same pause
  the document uses now: a run of typing comes off in one press, and Enter, a paste or typing
  over a selection each stay a step of their own.
- **Images crop, and the alt text has a menu worth reading.** Image blocks are editable rather
  than decorative now: a crop that stays inside the image's own bounds, paste support in the
  demo, and an alt menu shaped like the rest of the editor's menus.
- **Inline delimiters pair themselves.** Typing one half of `**`, `_`, `` ` `` or a plugin's own
  syntax writes the twin behind the caret; typing the closer steps over it rather than doubling
  it, whether or not the closer is visible in the mode you are in; an empty pair collapses; and
  Backspace between the two halves takes both. A plugin opts its own syntax in through the
  inline-syntax registry.
- **Drag handles are on by default.** They show for the blocks a drag actually means something
  for, stay out of tables, and stay off text-like blocks where the gesture would fight with
  selecting words.
- **Task checkboxes match GitHub's.** The box sits at the margin, fills with the text colour,
  centres its tick, and does not shift the line when you toggle it. A done item dims instead of
  being struck through.
- **Two heading and list behaviors stopped being surprising.** Enter at the very start of a
  heading moves the heading down under a new line instead of splitting it, an empty heading
  demotes to a paragraph when you leave it, and Shift+Enter inside a list item paints a real
  new line rather than a backslash.
- **Drag-select can start in the margin.** A drag beginning beside the text now selects, within
  a block or across several, and releasing keeps what you selected. The overlay merges its rects
  per line, so a widget no longer gets painted over twice, and it re-measures when a block
  changes size under it.
- **A host is told when a menu opens.** The new `menuChange` event fires on the open and close
  of the editor's own menus, so app chrome, a floating toolbar above all, can step aside instead
  of overlapping. `runCommand` also takes an argument now, for commands that need one.
- **Bold and italic come off a selection that reaches past the word.** Selecting ` word` and
  pressing Ctrl+B wrote `**word**` with the space kept outside, since a run cannot close against
  whitespace, and the same selection pressed again did nothing: the unapply read the space as
  uncovered. The toggle now reads a selection through its boundary whitespace, so a second press
  strips what the first wrote, and a toolbar asking whether the mark is on gets the same answer.
  Styled source kept that space inside the delimiters, where no reader parses it as bold and the
  next press doubled them. Every mode wraps the word alone now, a code span included, which is
  what a press across several blocks always did.
- **A click on an equation puts the caret where you clicked.** Every click on a rendered `$$`
  block opened its source with the caret past the closing fence, so editing the head of a formula
  was a click and then a walk back through it. The press names a place in the equation now, and a
  click beside the ink takes the glyph nearest it. Arriving by keyboard is unchanged.
- **A block selected whole takes typing, paste and cut.** Dragging inside a rule or a rendered
  equation selects that block, and only Backspace acted on it: a character, a paste and a cut
  reached nothing, because the block holds no place for a caret and the keystroke landed on the
  editor itself. All four gestures go through the selection now: a character or a paste puts its
  own bytes where the block stood, a cut takes the block out and writes it to the clipboard, and
  each is one undo. A block emptied by any of them leaves no husk behind either: cutting an
  equation used to leave the blank line it stood on. Hosts reading `replaceBlock` see the source
  `cross-block-covered-block` where the whole-table paste reported `cross-block-paste-whole-table`.
- **The demo opens live and light.** It is the mode and the theme most people want first. The
  page is a full-width scroller with a centred column, so the document has room without the
  text running edge to edge.

### 0.10.2: an editor you can see on a white page

- **An editor with no theme of its own inherits the page's text color.** The root's text fell
  back to white whenever no host token and no `aragonite-editor-theme` wrapper set it, so the
  README's own snippet mounted white text on a fresh app's white page: you could type, and the
  spellcheck squiggle was the only sign you had. The fallback is `currentColor` now, so an
  unthemed editor reads in its page's own color, and the parrot's caption follows suit. The
  quickstart snippet gained the wrapper it always needed, saying `light` in both places that
  have to match the page.

### 0.10.1: large documents, the plugins prop, and a phone

- **A line that only becomes a heading with the line under it now joins it right away.** Pressing
  Enter in a heading standing above a bare `===` left two paragraphs on screen, though saving and
  reopening read them as one underlined heading. Any edit that puts a line directly above its
  `===` or `---` underline, or above a table's delimiter row, now folds the pair into the one
  block a reopen would show.
- **A format toggle across a giant table lands.** Selecting a table of tens of thousands of cells
  and pressing Ctrl+B did nothing at all: working out which cells the range covers handed every
  one of them to a single call, and past a certain count the engine refuses the call outright.
  The cells are gathered one at a time now, so the toggle writes, and a toolbar asking whether
  the format is already on gets an answer instead of an error.
- **A paste of a very large document lands.** Pasting more than about a hundred thousand blocks
  at once did nothing at all, for the same reason: every block went to a single call, and past a
  certain count the engine refuses the call outright. Each splice a document or a clipboard can
  scale now writes in bounded batches, so the paste lands, and so do a replace-all producing that
  many blocks and a fold over a container that wide.

- **The party parrot dances in CSS.** Its frames used to be swapped by a script timer that ran
  fourteen times a second whether or not the block was on screen, and the block's own text
  changed with every frame. All ten frames now sit in the DOM as one strip that CSS scrolls a
  frame at a time, so the dance costs no script, the bird's box stops resizing under it, and
  `prefers-reduced-motion` parks it on a single frame.

- **A plugin can say where a click lands in its own block.** `caretTargetAtPoint` was a
  descriptor field the editor read and no plugin could honestly fill: turning a press into a
  character offset means walking the DOM the way the caret does, and nothing on the plugin
  surface did it. `caretOffsetAtPoint` now does, taking one of your own elements and the press
  and answering the offset nearest it, with `CaretTarget` naming the shape the hook returns and
  `CURSOR_END` finally importable for a hook that means "wherever that leaf ends".

- **Enter works in a one-line plugin block.** Pressing it in a party parrot's caption used to
  type a newline the block had no way to show, so nothing appeared to happen. A leaf whose bytes
  are one line now says so with `createEditableLeaf`'s new `singleLine` option, and Enter ends
  the block the way it ends a heading: the text after the caret becomes a paragraph below, with
  the caret in it.
- **Decorations repaint on the keystroke that moved the text.** Marks, badges and islands
  followed the editor's batched edit event, which waits out a quarter-second typing pause, so
  an occurrence highlight visibly dragged behind the word it was painted over while you typed.
  Every decoration source now re-runs on each document change instead.
- **The occurrence highlight steps aside while you type.** Now that the marks keep up with the
  bytes, keeping up turned out to be the wrong thing to do: the word under your caret, and every
  copy of it on the page, lit up while you were still writing it. The marks clear on the first
  keystroke of a burst and come back a quarter-second after the last one, which is the editor's
  own typing pause rather than a timer the plugin brought along.
- **An editor runs only the plugins it was given.** The `plugins` prop is now the enablement
  set: an editor attaches the hooks, resolves the kinds, answers the commands and applies the
  paste transforms of exactly the plugins it lists, and a plugin another editor on the page
  installed does nothing here. Registration is still process-wide and still first-wins, and an
  editor mounted with no `plugins` prop still gets everything installed. This is how the demo
  keeps the occurrence highlight off until you ask for it: the toggle adds the plugin to the
  array.
- **A decoration source can invalidate itself from an edit handler.** `invalidate()` re-ran the
  source there and then, and an `edit` handler is called part-way through the commit that emitted
  it, so the source read a document the editor had not finished publishing. Such a call now waits
  for the commit, and several of them in one commit are one re-run. Everywhere else `invalidate()`
  stays synchronous.
- **A plugin's shortcut belongs to the editors that asked for it.** A global chord registered
  by any plugin on the page was swallowed by every editor on the page, so in an editor whose
  `plugins` array left that plugin out the key did nothing and reached neither the plugin nor
  the app around it. The chord now runs, is reported by `reservedChords()`, and is claimed by
  `claimsChord()` only in the editors that listed its plugin.
- **A paste reads the grammar of the editor it lands in.** Pasting into a paragraph, a code
  block or a table cell parsed the clipboard against every plugin installed in the process, so
  text written in a plugin's syntax became that plugin's block even in an editor whose `plugins`
  array left the plugin out, and the block then had no component to render it. Every paste route
  now parses through the same grammar the rest of that editor reads.
- **Footnote references and definitions jump to each other.** A plain click on a reference in
  reading mode, or Ctrl/Cmd+click while editing, lands the caret in the definition's body, and a
  click on the definition's `[^label]` marker lands it back after the first reference. Backspace
  at the start of a definition's body lifts that paragraph out of the note instead of doing
  nothing.
- **The party parrot ships as a bundled plugin.** `@voithos-labs/aragonite/plugins/parrot` is
  the plugin guide's quickstart, verbatim. Its caption is what you see at rest; the caret
  entering the block reveals the `%%parrot` line, and leaving it commits the edit as one undo
  entry.
- **The table's row and column grips follow `blockDragHandles`.** They painted whether or not
  the prop was on; now they show only when handles are on, like every other block's grip.
- **Typing inside a huge list or quote no longer slows down with the container.** A keystroke
  rewrites the one child's bytes inside its container's source instead of re-reading every
  child, so the cost tracks the block you are editing rather than the thousands around it. A
  25,000-item list was paying 17.7 ms per keystroke on a production build before this; it pays
  3.3 ms after, and a 250,000-item one 5.4 ms.
- **A party parrot scrolls in its own box.** The bird is wider than a phone column, and it used
  to take the whole document sideways with it, so a swipe right slid the text out from under the
  header. It scrolls itself now, the way a code block or a wide table already did.
- **Drag handles and table grips show up on a touch screen.** Both were revealed by hovering,
  which a finger never does, so `blockDragHandles` did nothing at all on a phone: the handle sat
  in the DOM permanently invisible. Where the pointer can't hover they now show at rest, and the
  grip itself takes the touch rather than the whole gutter beside it.
- **The find bar stays inside a narrow editor.** It was pinned to the right at a fixed width, so
  in a column much under 470px it ran off the left edge and the input couldn't be tapped at all.
  It now caps at the editor's width and wraps to a second row instead of overflowing.
- **Link and URL text is readable in both themes.** The accent color was one value serving a
  near-black editor and a white one, and it sat below the WCAG AA contrast line on the dark
  background and inside code blocks in either mode. It now carries a light and a dark value like
  every other color token, so links, URLs and the code fence's language label clear AA wherever
  they land. A host that declares `--color-accent` itself is unaffected.
- **Comments and keywords in a code block are readable on the fence.** The dark palette's Monokai
  pink and its comment grey both sat under the WCAG AA contrast line against the shaded background
  a code block paints behind them, and the light palette's comment grey missed it there too. All
  three keep their hue and clear AA now, on the editor surface and inside the fence.
- **Two costs paid once per block at load got cheaper.** Block identity comes off a counter
  rather than a UUID per block, and the height model seeds each block with fewer reads. Both scale
  with the block count of the whole document, which is what makes a 400,000-block load slow:
  3.2 s before, 2.0 s after, on a production build.
- **Backspace at the start of a directive's body lifts that paragraph out.** Pressed at the
  head of the first block inside a `:::name` container it did nothing at all: no bytes changed
  and the caret stayed put. It now lifts the block out above the container the way it does in a
  blockquote or a footnote, and the fences close over whatever body is left. A container whose
  first row is a title (the callouts, details) still declines the press, and now says so by
  name rather than by leaving a field out.

### 0.10.0: reload truth at every door, and windowing under host scroll

- **Host-scrolled documents window.** A page-scrolled shell (an app embedding the editor in
  its own scrolling page) now gets the same O(viewport) typing and mounting as a standalone
  editor: windowing reads a scrollport the scroll mode resolves, activation stays gated on the
  height budget alone, and a windowing editor withdraws its subtree from the host's native
  scroll anchoring and corrects by hand. `placeCaretAtPoint` below a windowed-out tail reveals
  the target before landing.
- **The live tree now converges with its own reload at every mutating door.** A demoted
  heading merges with the neighbours it stopped interrupting — above and below, with the caret
  following the typed byte; deleting an ordered list's first item folds the renumbered list
  into a tight paragraph above; a reorder, a nested edit, and a whole-body blank run under a
  callout all reload to exactly the shape they show. What a save writes is what a reopen reads.
- **A typed fence closes itself instead of swallowing the document.** Typing ` ```mermaid `,
  ` ``` `, or a math fence above other blocks mints the closing fence over an empty body; the
  blocks below stand. A gesture that merely exposes an existing open fence still folds, which
  is the reload's honest reading.
- **Whole-block kinds take AltGr, IME, and dead-key input.** A focused thematic break or
  diagram hosts a hidden editing surface on the gap caret's model, so composed and layout-mapped
  characters mint a paragraph instead of dropping; the tab order treats the block as one stop
  in each direction.
- **Footnote numbering costs the edited subtree, not the document.** With a reference mounted,
  the 1 MB keystroke p50 fell from 50 ms to 11.7 ms (100 KB: 8.2 to 4.1) by memoizing each
  top-level subtree's contribution against its bytes.
- **Three consumer doors.** `normalizeSelection` (document order over selection endpoints),
  `getBlockKindAt(path)` (the kind at a path, no DOM probing), and `canRunCommand(id)` (the
  dispatch seam's own admissibility, for greying a toolbar button) — resolved through the same
  tier walk the dispatch spends, so read and run cannot disagree. The demo toolbar rides all
  three.
- **Per-instance options reach plugin factories.** Leaf and container factories take a
  `getOptions()` thunk beside the block-command context's, and the bundled toc plugin reads its
  depth per instance, so two editors in one process render different depths.
- **Table cells follow the mode and theme.** A cell's inline widgets read the presentation
  mode and theme, and a mode flip rebuilds a cell's inline DOM the way it rebuilds a prose
  block's.
- **Paste fixes.** A pasted list ending in a table no longer takes a line ending inside the
  row; a clipboard's trailing blank line survives a paste at the document tail, in the
  document's own line-ending flavor.
- **A drag released on a whole-block kind ends there.** Releasing a selection drag over a
  thematic break or a diagram used to leave the endpoint in the block above, so the selection
  stopped short of what was highlighted; the hit test now answers with the block under the
  pointer.
- **A plugin container can declare its surface non-editable.** A container kind whose body is
  its own rendering, not text a caret belongs in, says so on its descriptor, and the editor
  treats it that way rather than making the author fake it.
- **The landable-caret guard covers every caret door.** G1.33 fires from the editor root's
  focus seam, so a plugin's own caret door and the render-primary reveal inherit the guard a
  built-in surface always had.
