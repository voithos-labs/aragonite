# Changelog 0.10

Newest first; the index is [`../changelog.md`](../changelog.md).

### 0.10.1: large documents

- **Decorations repaint on the keystroke that moved the text.** Marks, badges and islands
  followed the editor's batched edit event, which waits out a quarter-second typing pause, so
  an occurrence highlight visibly dragged behind the word it was painted over while you typed.
  Every decoration source now re-runs on each document change instead.
- **The occurrence highlight steps aside while you type.** Now that the marks keep up with the
  bytes, keeping up turned out to be the wrong thing to do: the word under your caret, and every
  copy of it on the page, lit up while you were still writing it. The marks clear on the first
  keystroke of a burst and come back a quarter-second after the last one, which is the editor's
  own typing pause rather than a timer the plugin brought along.
- **The occurrence highlight is switched per editor.** Pass
  `{ plugin: highlightOccurrencesPlugin(), options: { enabled: false } }` in the `plugins` prop
  and that editor attaches nothing. Installation stays process-wide, so this is the switch for
  one editor of several, and it's how the demo keeps the highlight off until you ask for it.
- **Footnote references and definitions jump to each other.** A plain click on a reference in
  reading mode, or Ctrl/Cmd+click while editing, lands the caret in the definition's body, and a
  click on the definition's `[^label]` marker lands it back after the first reference. Backspace
  at the start of a definition's body lifts that paragraph out of the note instead of doing
  nothing.
- **The party parrot ships as a bundled plugin.** `@voithos-labs/aragonite/plugins/parrot` is
  the plugin guide's quickstart, verbatim. Its caption is what you see at rest; the caret
  entering the block reveals the `%%parrot` line, and leaving it commits the edit as one undo
  entry.
- **The table's row and column grips follow `blockDragHandles`.** They painted whether or not
  the prop was on; now they show only when handles are on, like every other block's grip.
- **Typing inside a huge list or quote no longer slows down with the container.** A keystroke
  rewrites the one child's bytes inside its container's source instead of re-reading every
  child, so the cost tracks the block you are editing rather than the thousands around it. A
  25,000-item list was paying 17.7 ms per keystroke on a production build before this; it pays
  3.3 ms after, and a 250,000-item one 5.4 ms.
- **Two costs paid once per block at load got cheaper.** Block identity comes off a counter
  rather than a UUID per block, and the height model seeds each block with fewer reads. Both scale
  with the block count of the whole document, which is what makes a 400,000-block load slow:
  3.2 s before, 2.0 s after, on a production build.

### 0.10.0: reload truth at every door, and windowing under host scroll

- **Host-scrolled documents window.** A page-scrolled shell (an app embedding the editor in
  its own scrolling page) now gets the same O(viewport) typing and mounting as a standalone
  editor: windowing reads a scrollport the scroll mode resolves, activation stays gated on the
  height budget alone, and a windowing editor withdraws its subtree from the host's native
  scroll anchoring and corrects by hand. `placeCaretAtPoint` below a windowed-out tail reveals
  the target before landing.
- **The live tree now converges with its own reload at every mutating door.** A demoted
  heading merges with the neighbours it stopped interrupting — above and below, with the caret
  following the typed byte; deleting an ordered list's first item folds the renumbered list
  into a tight paragraph above; a reorder, a nested edit, and a whole-body blank run under a
  callout all reload to exactly the shape they show. What a save writes is what a reopen reads.
- **A typed fence closes itself instead of swallowing the document.** Typing ` ```mermaid `,
  ` ``` `, or a math fence above other blocks mints the closing fence over an empty body; the
  blocks below stand. A gesture that merely exposes an existing open fence still folds, which
  is the reload's honest reading.
- **Whole-block kinds take AltGr, IME, and dead-key input.** A focused thematic break or
  diagram hosts a hidden editing surface on the gap caret's model, so composed and layout-mapped
  characters mint a paragraph instead of dropping; the tab order treats the block as one stop
  in each direction.
- **Footnote numbering costs the edited subtree, not the document.** With a reference mounted,
  the 1 MB keystroke p50 fell from 50 ms to 11.7 ms (100 KB: 8.2 to 4.1) by memoizing each
  top-level subtree's contribution against its bytes.
- **Three consumer doors.** `normalizeSelection` (document order over selection endpoints),
  `getBlockKindAt(path)` (the kind at a path, no DOM probing), and `canRunCommand(id)` (the
  dispatch seam's own admissibility, for greying a toolbar button) — resolved through the same
  tier walk the dispatch spends, so read and run cannot disagree. The demo toolbar rides all
  three.
- **Per-instance options reach plugin factories.** Leaf and container factories take a
  `getOptions()` thunk beside the block-command context's, and the bundled toc plugin reads its
  depth per instance, so two editors in one process render different depths.
- **Table cells follow the mode and theme.** A cell's inline widgets read the presentation
  mode and theme, and a mode flip rebuilds a cell's inline DOM the way it rebuilds a prose
  block's.
- **Paste fixes.** A pasted list ending in a table no longer takes a line ending inside the
  row; a clipboard's trailing blank line survives a paste at the document tail, in the
  document's own line-ending flavor.
- **A drag released on a whole-block kind ends there.** Releasing a selection drag over a
  thematic break or a diagram used to leave the endpoint in the block above, so the selection
  stopped short of what was highlighted; the hit test now answers with the block under the
  pointer.
- **A plugin container can declare its surface non-editable.** A container kind whose body is
  its own rendering, not text a caret belongs in, says so on its descriptor, and the editor
  treats it that way rather than making the author fake it.
- **The landable-caret guard covers every caret door.** G1.33 fires from the editor root's
  focus seam, so a plugin's own caret door and the render-primary reveal inherit the guard a
  built-in surface always had.
