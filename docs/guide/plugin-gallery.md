# Plugin Gallery

The listing, the plugin check and the plugin template are a preview until 0.12.0: the API under them can still change in any 0.11 release.

Plugins other people wrote for aragonite, plus the bundled ones. Every one is an ordinary npm package that lives in its author's own repository; this page only lists them, and the editor checks each one against every release. The table is [at the bottom](#the-plugins).

## What "passed" means

"Passed on 0.12.3" means one thing: on editor release 0.12.3, `aragonite-plugin-check` installed the plugin beside the editor, ran the conformance kits over the suite the package publishes, and every cell passed. Those are the checks every built-in block is held to: the bytes round-trip, one edit is one undo step, a copy invents nothing, and the rest of [the kits](plugin-testing.md#the-conformance-kits).

It isn't a code review, and it isn't a security check. A plugin runs inside your app with everything your app can do, the way any npm package does, so read what you install. A plugin that fails at the next release, or whose peer range leaves that release out, says so in the table instead of "passed".

## Finding more

Not every plugin is listed here. Search npm for the [`aragonite-plugin` keyword](https://www.npmjs.com/search?q=keywords:aragonite-plugin), which every plugin should carry, listed or not.

## Getting your plugin listed

Start from the [plugin guide](plugin-guide.md#the-first-fifteen-minutes)'s template if you haven't yet, since it comes with everything below wired up. To be listed, a plugin needs:

- **A package on npm**, named `aragonite-<name>` or `@your-scope/aragonite-<name>`, with the `aragonite-plugin` keyword.
- **A `./conformance` export** whose default export is your [conformance suite](plugin-testing.md#the-whole-plugin-at-once-runpluginconformance): your plugins, plus a profile for each container or inline kind they declare.
- **A passing check.** `npx aragonite-plugin-check your-package` in a project with both installed runs exactly what the listing runs.

Then open a pull request on the editor's repository that adds one entry to [`listing.json`](plugin-gallery/listing.json), in order by package name, and regenerates the table below with `node scripts/plugins/listing.mjs --write`:

| Field        | What goes there                                                              |
| ------------ | ---------------------------------------------------------------------------- |
| `package`    | Your npm package's name                                                      |
| `repository` | Its source repository's https URL                                            |
| `editor`     | The editor versions you support, as an npm range (`^0.12.0`)                 |
| `verified`   | `null`. The check writes this one, on your pull request and at every release |

The pull request runs the check over your published package. Your code stays in your repository, and so do your releases: the listing never hosts a plugin's source.
